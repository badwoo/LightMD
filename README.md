# LightMD

> 一款**轻量级**、**高性能**、**所见即所得**的 Windows Markdown 编辑器，基于 Tauri v2 + React + ProseMirror 构建。

**当前版本：v0.8.5**

中文 | [English](./README_EN.md) | [用户指南](./USER_GUIDE.md)

## ✨ 为什么选择 LightMD？

LightMD 是一款**专为 Windows 平台**打造的轻量级 Markdown 编辑器，融合了传统 Markdown 的简洁和现代 WYSIWYG 编辑器的直观。安装包仅 **~7MB**，启动毫秒级，深度集成 Windows 桌面体验。

## 🎯 核心特性

### 📝 三种编辑模式

- **阅读模式** — 所见即所得，光标所在行显示 Markdown 语法标记
- **源码模式** — 纯文本编辑，配合工具栏快捷插入语法
- **分屏模式** — 左右同步滚动，编辑与预览实时联动

### 📊 富文本支持

- ✅ 标准 Markdown（标题、列表、引用、代码块、表格、链接、图片）
- ✅ **GFM 任务列表**（`- [x]` / `- [ ]`）
- ✅ **Mermaid 图表**（流程图、时序图、甘特图、类图、状态图等 20+ 种，工具栏内置 7 种模板一键插入）
- ✅ **KaTeX 数学公式**（行内 `$...$` 与块级 `$$...$$`；块级公式编辑态实时预览，0.5.0 新增）
- ✅ **代码语法高亮**（PrismJS，200+ 语言，0.2.0 新增 PHP/Swift/Kotlin/Dart/Lua/Ruby/R/Scala/Perl/PowerShell；0.5.0 新增无语言标注代码块自动识别语言）
- ✅ **高亮标记** `==文本==`（0.2.0 新增）
- ✅ **上标 / 下标** `^文本^` / `~文本~`（0.2.0 新增）
- ✅ **Emoji 表情** `:smile:` 自动补全（0.2.0 新增）
- ✅ **脚注** `[^1]` + `[^1]: 说明`（0.2.0 新增）
- ✅ **定义列表** `术语\n: 定义`（0.2.0 新增）
- ✅ **自动目录** `[toc]` 或 `[[toc]]`（0.2.0 新增）
- ✅ **锚点链接** — 标题自动生成 id，支持 `[链接](#标题)` 跳转（0.2.0 新增）

- 🖱 **表格右键菜单** — 阅读模式下右键表格可插入/删除行与列（0.2.0 新增）
- 📊 **底部状态栏** — 显示字数/行号/光标位置，集成搜索/专注/打字机快捷按钮（0.3.4 新增）
- 📑 **代码文件支持** — 直接打开 .js/.py/.ts 等代码文件，阅读模式 PrismJS 语法高亮（0.4.0 新增）

### 🪟 多窗口（0.9.0 新增）

- 🪟 **对等多窗口** — `Ctrl+Shift+N` 或标题栏「窗口」菜单新建辅助窗口（上限 8 个）；每个窗口拥有**独立的标签页、编辑器状态、浏览进度与 AI 对话窗**
- 🔁 **全局状态实时同步** — 主题、字体、侧栏宽度、AI 配置、最近打开、收藏夹在所有窗口间即时同步
- 📂 **多入口在新窗口打开** — 文件树右键 / 左侧栏「打开的文件」右键「在新窗口中打开」、标签右键「移动到新窗口」（临时标签连内容一起迁移）、**按住标签拖出标签栏**直接移动到新窗口、`Ctrl+Alt+O` 选择文件并在新窗口打开
- 🗂 **标题栏「窗口」菜单** — 动态列出各窗口及其标签（含未保存圆点）：点击窗口项激活窗口，点击标签子项激活窗口并切换标签；另有「合并到主窗口」（也可直接把辅助窗口的标签拖到主窗口标签栏，松手即询问是否合并）
- 🪟 **窗口拖拽合并** — 把辅助窗口拖到主窗口的标签栏一带并停住，弹出「合并回主窗口？」确认后全部标签并入主窗口并关闭自身（0.9.0 第三轮新增）
- ⚔️ **文件冲突检测** — 同一文件已在其他窗口打开且含未保存更改时，打开前弹应用内对话框（只读打开 / 强制编辑 / 切换到已有窗口 / 取消）；只读标签标题显示 `[只读]`
- 👀 **外部修改与删除联动** — 已打开文件被其他程序修改时，干净标签自动重载并提示、脏标签标记待确认；文件被删除时自动关闭对应标签
- 🤖 **AI 任务窗口隔离** — 窗口 A 的翻译/续写/润色/摘要/对话不再顶掉窗口 B 的任务；同窗口内仍是新任务取消旧任务
- 💾 **多窗口会话恢复** — 新增「启动时恢复其他窗口」开关（默认关闭，只恢复主窗口；开启后恢复**上次会话的全部窗口**——逐个关窗退出后重开也能整体还原）与「退出 LightMD」动作（`Ctrl+Q`，只记录**主窗口**，下次启动不恢复其他窗口）；合并到主窗口的窗口不会重复复活
- 👀 **外部修改与删除联动** — 干净标签被外部修改时自动重载并提示；**应用自身保存不再被误判为外部修改**（不会出现「保存即弹覆盖/另存为」的循环提示）；文件被删除时自动关闭对应标签
- ✅ **智能关闭确认** — 关闭窗口 / 退出应用只对**已落盘且未保存**的文件提示；临时（未命名）标签的内容会被自动记忆并在下次启动恢复，不再因此弹窗
- 🧹 **向后兼容** — 不使用多窗口时行为与 0.8.5 完全一致；主窗口沿用旧数据文件，零迁移

### ⚡ 性能优势

- **Tauri 2** Rust 后端 — 启动快、内存低、安装小
- **ProseMirror** 编辑器核心 — 大文档流畅编辑
- **iframe 隔离预览** — 预览 DOM 与主文档隔离，显著降低 GC 压力
- **增量 diff 撤销栈** — 仅存储差异而非全量快照，大幅节省内存
- **空闲零 CPU 占用** — 空状态动画仅使用合成层 opacity，窗口失焦自动暂停（0.4.5 优化）

- **多窗口会话恢复** — 重启后按原窗口、原标签、原活跃标签、原打开文件夹精确恢复；`session.json` 只存标签与文件夹元数据（不存几何、不存未保存正文）；「启动时恢复其他窗口」开启后，逐个关窗退出（关闭最后一个窗口 = 退出应用）也会把本会话的全部窗口整体还原，而「退出 LightMD」/ Ctrl+Q 显式退出只恢复主窗口

**架构与性能**

- **固定槽位窗口标识** — 辅助窗口使用 `sec-1` ~ `sec-7` 固定槽位，槽位复用使窗口几何（`tauri-plugin-window-state`）与窗口级 localStorage 数据跨会话天然复用，且无需随机 ID 依赖
- **窗口级 / 全局级状态分层** — 窗口级数据（临时标签、上次活跃标签、浏览进度、scratch 内容）按窗口后缀隔离；主窗口沿用无后缀旧 key，**零迁移**
- **目录 watcher 引用计数** — 多个窗口打开同一目录只注册一个 watcher，最后一个窗口关闭才注销
- **全局状态广播** — 事件广播携带 `sourceWindowId` 自忽略 + 同 tick 合并，避免乒乓风暴与广播风暴；文件库仅同步持久化白名单字段（高频的「打开的文件」镜像不参与）
- **AI 任务按窗口分桶** — 划词翻译 / 续写 / 润色 / 摘要 / 对话的单任务槽按窗口隔离，跨窗口互不取消；同窗口内仍是新任务取消旧任务（0.6.0 语义不变）
- **窗口状态上报** — 前端对标签元数据做指纹比对后才上报，避免每次击键产生 IPC

**修复（第二轮复测反馈）**

- **阅读位置不再被重置** — 修复窗口引导流程过早结束「会话恢复期」、导致重开软件后所有标签回到顶部的问题
- **主窗口标签/文件夹不丢** — 会话快照始终保留主窗口的最后状态；关闭最后一个窗口（退出应用）时必定重写会话，并把该窗口自身一并记录
- **不再误报「文件已被外部修改」** — 自身写盘增加 1.5s 抑制窗口 + 前端内容指纹比对，杜绝保存后右下角误报；磁盘内容一致时也不再重复提示「已自动重新载入」
- **「不保存」只影响是否写回磁盘** — 不再连带关闭标签；会话缺失主窗口条目时自动回退到最近文件恢复（升级自愈）
- **设置项描述样式** — 「启动时恢复其他窗口」的功能说明改为按钮后的小字号灰色提示

**优化与修复（第三轮复测反馈）**

- **「打开的文件」右键** — 左侧栏「打开的文件」条目右键新增「在新窗口中打开」（与文件树右键同一命令，本窗口标签保持不变）
- **标签拖出标签栏 → 移动到新窗口** — 鼠标左键按住标签拖到标签栏与侧栏之外松手即移动（未保存的真实文件先提示；未落盘临时标签连内容迁移）；拖到侧栏文件夹仍是复制/移动原语义；拖拽浮层提示「松开以移动到新窗口」
- **辅助窗口拖到主窗口标签栏 → 合并询问** — Rust 侧检测窗口几何（建窗忽略期 + 焦点闸门 + 500ms 静止去抖，杜绝误触发），停住后弹「合并回主窗口？」，确认即把全部标签并入主窗口并关闭自身；合并的窗口从会话快照除名，不会重复复活
- **逐个关窗退出后其他窗口不恢复（修复）** — 两个根因：① 退出（关闭最后一个窗口）时的会话快照丢了中途已关窗口的状态；② 上一轮引入的回归——`finalize_session` 在最后一个窗口关闭后又用"存活窗口=0"的快照**覆盖**了刚写好的退出快照。现在：窗口最后状态保留到进程结束，退出快照收录本会话全部窗口；`finalize_session` 恢复「仍有存活窗口才落盘」守卫
- **恢复语义修订** — 「启动时恢复其他窗口」开启 = 恢复上次会话的全部窗口（含退出时逐个关闭的）；「退出 LightMD」（`Ctrl+Q`）= 只记录退出时刻仍存活的窗口（第四轮再次修订为「只记录主窗口」，见下）；开关关闭 = 只恢复主窗口（原样）

**优化与修复（第四轮复测反馈）**

- **同文件多窗口保存后立即刷新** — 根因：防误报的"自身写入抑制"此前是**进程全局**的，某个窗口保存后所有窗口的事件都被吞掉，**其他**打开同一文件的窗口收不到变更、内容停在旧版本。现改为**按写入窗口**标记：事件照常广播并带 `source`（写入者），写入窗口据此忽略自己的回声（不再误报「文件已被外部修改」），其他窗口立即重载
- **标签拖到主窗口标签栏 → 合并询问** — 拖动辅助窗口的标签放到**主窗口标签栏**上松手，弹出「合并回主窗口？」，点「合并」即把该窗口全部标签并入主窗口并关闭自身；松手位置不在任何标签栏上时，维持「移动到新窗口」（第三轮行为不变）
- **「退出 LightMD」/ `Ctrl+Q` 后不再恢复其他窗口** — 显式退出只记录**主窗口**（下次启动恢复主窗口的标签/文件夹/浏览进度，其他窗口不出现）；逐个点右上角关闭（关掉最后一个即自然退出）仍按会话整体还原。退出前会绕过 300ms 防抖立即上报本窗口状态，确保快照就是"退出那一刻"的标签集合

**修复（Markdown 序列化往返，用户提交 689dcee）**

- 保存/重载往返不再改坏文档：22 项解析-序列化往返修复（软换行、emoji、引用与代码块边界等），附 590 行专项回归测试

**问题修复**

- **「打开的文件」栏双高亮** — 栏内点击条目 A 后从标签栏切到 B，A 残留的键盘选中背景与 B 的激活背景同时高亮（两者背景色原本相同），视觉混乱。现键盘选中项随激活条目变化失效（"栏内点击自己"的场景保留，保证点击 A 后直接按 `Delete`/`Ctrl+2` 仍关闭 A），并把键盘选中指示从"同色背景"改为**左侧 2px 竖线**，任何状态组合下都不会再出现两个高亮块

**性能**

- **选区变化不再全量序列化文档** — 此前每次光标移动/击键都执行一次 `doc.textContent`；现改为惰性取值，只在字数统计的 300ms 防抖回调里取一次。18k 行（66 万字符）文档实测：单次选区变化成本 **0.778ms → 0.072ms**（约 1/11）
- **图片懒加载** — 图片节点输出 `loading="lazy"` + `decoding="async"`，大图解码不再阻塞合成帧
- **滚动监听全部声明 `passive`**
- **滚动性能评测** — 用真实 Chromium 对 1.8 万行 / 9000 顶层块文档实测：基线滚动 avg **16.67ms（60fps、0 长任务）**，说明瓶颈既不在 Tauri/WebView2 框架层，也不在"整篇 DOM"这一层。计划中的 `content-visibility: auto` 方案实测反而把滚动拖慢到 avg **70.4ms（14fps、每帧一次 ~70ms 长任务）**——近万顶层块在滚动中持续做延迟布局，且估值尺寸与真实高度偏差（scrollHeight 被撑大 36%）引发大范围重排；**故不采用该方案**，结论与数据已写入源码注释，避免后人重复踩坑
