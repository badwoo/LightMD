# LightMD

> 一款**轻量级**、**高性能**、**所见即所得**的 Windows Markdown 编辑器，基于 Tauri v2 + React + ProseMirror 构建。

**当前版本：v0.15.6**

中文 | [English](./README_EN.md) | [用户指南](./USER_GUIDE.md)

## ✨ 关于LightMD

LightMD 是一款**专为 Windows 平台**打造的轻量级 Markdown 编辑器，融合了传统 Markdown 的简洁和现代 WYSIWYG 编辑器的直观。安装包仅 **~9MB**，启动毫秒级，深度集成 Windows 桌面体验。

## 🎯 核心特性

### 📝 两种编辑模式（v0.14.0：由三种合并为两种）

- **阅读模式** — 所见即所得，光标所在行显示 Markdown 语法标记
- **编辑模式** — 左源码 + 右实时预览（默认即原「分屏」）；右侧预览可一键收起成纯源码，
  收起后还能从编辑区右缘的竖排「打开预览」滑回来
  - 双击 `Ctrl`：阅读 ↔ 编辑；双击 `Shift`：编辑模式内开关右侧预览
  - **阅读进度不丢**：两种模式来回切换、甚至关闭标签后重新打开，都停留在原来的位置（0.14.0 第二批）
  - **撤销穿过模式切换**（0.15.0 新增）：每篇文档只有**一条逻辑时间线**，阅读 / 编辑 / 右侧预览共用同一份撤销栈；`Ctrl+Z` 可以从编辑态一路撤回到阅读态的修改，不会再出现"切模式后撤销失效"或"撤到别的模式的内容"
  - **阅读↔编辑按内容对齐**（0.15.0 新增）：两屏对齐由百分比改为**内容锚点**（顶层块 + 块内比例），同一段落始终落在同一屏对应位置；超长软换行、代码块、表格、图片、嵌套列表都按实测行轴换算，折叠的标题区间自动跳过
  - 分割线正中悬停浮出竖排呼吸小字「关闭预览 / 打开预览」

### 🚰 渲染管线统一与导出保真

- 分屏预览与全部导出格式（HTML / PDF / PNG / DOCX / LaTeX / ePub）共用同一 markdown-it 配置源：直引号不再被改写为弯引号，`javascript:` 等危险链接在所有导出路径拦截
- 导出时公式渲染为 KaTeX 排版（ePub 为原生 MathML）、Mermaid 图表渲染为矢量图，不再是空白占位或源码文本
- 搜索替换支持正则与 `$1` / `$&` 捕获组引用，非法正则红字提示不崩溃
- 大纲渲染上限 1000，长文档不截断

### v0.15.6（2026-11-03）

**配置交互重构 —— 服务商与自定义两个页签统一为「条目式」：点条目展开/收起、条目上独立开关、绿点标启用**

| 要点 | 实现 |
| --- | --- |

**回车 = 换行 —— 三模式换行数一一对应、行距恢复默认**（基线 0.12.2）

用户反馈两条现象：① 阅读模式编辑文本，只按一次回车，切到编辑/分屏模式却凭空多出一个空行；② 阅读模式编辑文字行间距很高，与打开的其他文档观感不一致。两者**同源**：阅读模式回车走的是 `baseKeymap.splitBlock`（新建段落），而 Markdown 段落之间必须有空行。

**问题修复**

| 项                    | 内容                                                                                                                                                                                                                                                                                       |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 阅读模式凭空多空行            | 顶层普通段落内改&#x4E3A;**「行内回车 = 段内换行」**（`hard_break`）：按一次回车 = 源码里**一个换行**（相邻两行、无空行），按两次 = **一个空行**，按 N 次 = N 个换行 —— 阅读模式里有几个回车换行，编辑/分屏模式就对应几个。作用域严格限定**顶层普通段落**，列表 / 任务项 / 引用 / 标题 / 表格 / 代码块语义零回归（列表内回车仍继续分裂条目）                                                                               |
| 阅读模式行距忽大             | 上述"新建段落"还会叠加 `.ProseMirror > p` 的 0.8em 上下 margin —— headless Chrome 实测段间行距 **41px**，而正常行高只有 **28.8px**，比段内换行明显更松。改为段内换行后行距回归行高（同一探针实测 **29px ≈ 编辑区 28.8px**），三模式逐像素一致                                                                                                                   |

### v0.9.1（2026-09-30）

**设置体验修复 · 快捷键弹窗 3×3 改版 · 沉浸式全屏重做**（基线 0.9.0；6 项需求）

**问题修复**

- **`Ctrl+,` 打不开设置（根因在输入法，不在应用）** — 用真实硬件级 `SendInput` 注入 + 页面内 keydown 取证定位：中文输入法（微软拼音等）把 `Ctrl+,` 作为**输入法保留键**在消息进入应用之前消费，页面只能收到 `Ctrl` 按下、逗号的 keydown 根本不存在（对照：`Ctrl+F` / `Ctrl+P` / `Ctrl+;` / `F11` 都能正常到达）。WebView2 的浏览器加速键开关也管不到这一层。修法：Rust 侧在本应用处于前台时用 **`RegisterHotKey`**（注册在 win32k 原始输入层，位于输入法与所有用户态钩子之前）把该组合抢回来，转成应用内事件；失焦立即注销，其它程序与输入法照常使用 `Ctrl+,`
  - 曾尝试低级键盘钩子（`WH_KEYBOARD_LL`）：回调超时会被 Windows 静默摘掉，且输入法自身也会装钩子并在前台切换时插到链首，拦截不稳定 —— 已改为系统热键方案
- **`F11` 等按键到不了页面** — WebView2 的 `AreBrowserAcceleratorKeysEnabled` 默认为 `true`，`F11`（浏览器全屏）、`Ctrl+P`、`Ctrl+F` 等浏览器加速键被 WebView2 在页面前就地消费，应用内的按键处理从不执行（真实 `F11` 走的是 WebView2 自带全屏，这正是"类似浏览器的全屏"观感的来源）。现于每个窗口创建时取 WebView2 控制器关闭该接管（Tauri 2.11 未透出该开关，直接调用 `ICoreWebView2Settings3::SetAreBrowserAcceleratorKeysEnabled(false)`）
- **设置弹窗出现瞬间"背景杂乱、不平滑"** — 根因与 v0.8.5 修复新建弹窗时同源：遮罩挂在弹窗容器本体上做淡入，**父元素的透明度会把整棵子树作为一组合成**，弹窗在半透明期间是"透"的 —— 背后的编辑器文字透过弹窗显形，又随弹窗的 20px 位移逐帧移动；遮罩自身还从全透明起步，第一帧整屏仍亮。现遮罩移到 overlay 的 `::before` 独立层（只动一个纯色层的透明度），弹窗本体只做一次淡入 + 8px 上浮，背景不再透出

- **「打开的文件」栏双高亮** — 栏内点击条目 A 后从标签栏切到 B，A 残留的键盘选中背景与 B 的激活背景同时高亮（两者背景色原本相同），视觉混乱。现键盘选中项随激活条目变化失效（"栏内点击自己"的场景保留，保证点击 A 后直接按 `Delete`/`Ctrl+2` 仍关闭 A），并把键盘选中指示从"同色背景"改为**左侧 2px 竖线**，任何状态组合下都不会再出现两个高亮块

#### v0.7.5 细节优化（同日追加）

**1. 修复按 Esc 关闭 AI 气泡/对话窗后文档跳回开头**

- 根因：气泡的 Esc 处理在 `window` 捕获阶段 `stopPropagation()`，编辑器 DOM 的**捕获 keydown 收不到该键**，但 keyup 不受影响仍到达编辑器；滚动跟随逻辑因此拿"上一次按键"遗留的 `savedScrollTop / savedCursorY` 计算，命中分支后把 `scrollTop` 恢复成旧值 —— 上一次按键若在文档开头附近，文档就跳回开头（是否需要跳取决于上次按键位置与当前滚动位置的差值，故表现为"有概率"）
- 修复：新增 `ScrollKeyBaseline`（keydown 记录 / keyup 消费），**只有见过配套 keydown 的 keyup 才允许进入滚动跟随**；焦点离开编辑器时作废基线；阅读模式（ProseMirror）与源码模式（textarea）打字机滚动同步修复

**2. 气泡颜色同步到底部栏 AI 按钮**

- 续 / 润 / 摘 / AI对话 四个抽屉按钮按任务注入 `--ai-entry-color`（取自对应气泡颜色），鼠标悬停与按下时以该色高亮；未设色时回退主题 accent，外观与旧版一致

**3. AI 续写立即给出反馈**

- 点击续写后**立即**在光标处渲染灰色占位 ghost「续写中...」（带呼吸动画），首个增量到达即替换为真实内容

- 阅读模式与源码模式行为一致

**4. AI 对话窗口内嵌 AI 翻译**

**5. 打开对话窗口的拖动限制**
