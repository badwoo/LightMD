# LightMD v0.9.0 发布说明

**发布日期**：2026-09-27  
**基线版本**：v0.8.5  
**主题**：对等多窗口 —— 独立标签·全局同步·冲突检测·会话恢复  
**实现依据**：`.trae/documents/LightMD_MultiWindow_PRD_v0.9.0.md` + `.trae/documents/lightmd-v0.9.0-implementation-plan.md`

## 一、版本内容

### 1.1 对等多窗口（Peer Window）

**窗口模型**

- 每个窗口拥有**独立的标签页集合、编辑器状态、浏览进度、AI 对话窗**；主题 / 字体 / 侧栏宽度 / AI 配置 / 最近打开 / 收藏夹在**所有窗口间实时同步**。
- 窗口上限 **8 个**（`main` + `sec-1` ~ `sec-7` 固定槽位），超出时 toast 提示。
- 关闭主窗口后由**最老的辅助窗口自动晋升**为主窗口，应用不退出；关闭最后一个窗口才退出。

**打开入口**

| 入口 | 行为 |
| --- | --- |
| 文件树右键 →「在新窗口中打开」 | 新建窗口并打开该文件 |
| 标签右键 →「移动到新窗口」 | 原窗口关闭该标签，新窗口打开（临时标签连内容一起迁移） |
| `Ctrl+Shift+N` / 标题栏「窗口」菜单 / 命令面板 | 新建空白窗口 |
| `Ctrl+Alt+O` / 命令面板 | 选择文件并在**新窗口**打开 |
| 双击 `.md` 等关联文件 | 按设置「外部文件打开方式」路由（当前窗口 / 新窗口 / 每次询问） |

**标题栏「窗口」菜单**：动态窗口列表（显示每个窗口的标签与未保存圆点），点击窗口项激活该窗口，点击标签子项**激活窗口并切换标签**；另有「新建窗口」「关闭当前窗口」「合并到主窗口」。

### 1.2 状态隔离与同步

- **窗口级**（严格隔离）：编辑器标签与活跃标签、视图模式、光标选区、临时（未命名）标签、上次活跃标签、浏览进度、AI 对话窗、侧栏打开的文件夹、冲突检测登记。
- **全局级**（实时同步）：主题、字体、侧栏/大纲宽度、分屏比例、AI 配置、文件树排序、最近文件/文件夹、收藏夹、会话文件夹快照。
- 同步实现为 Tauri 事件广播 + 对端 `rehydrate`，广播携带 `sourceWindowId` 自忽略，并对同一 tick 内的多次变更做合并，无乒乓风暴。
- **零迁移**：主窗口沿用 v0.8.5 的无后缀 localStorage key，老数据原地可用；辅助窗口使用 `-sec-N` 后缀。

### 1.3 文件冲突与外部变更

- 打开文件前查询「是否已在其他窗口打开且含未保存更改」：是则弹**应用内四选一对话框**（只读打开 / 强制编辑 / 切换到已有窗口 / 取消）。
- **只读打开**：编辑器不可编辑，标题栏显示 `[只读]`，仍可阅读、复制、导出。
- **强制编辑**：两个窗口均可编辑；若保存前检测到磁盘已被外部修改，弹「覆盖 / 另存为 / 取消」。
- **文件级监听**（上限 50 个文件）：干净标签被外部修改时自动重载并提示；脏标签只打标记并在保存时确认；文件被删除时自动关闭对应标签。
- 目录 watcher 改为**按窗口引用计数**：多个窗口打开同一目录只注册一个 watcher，最后一个窗口关闭才注销。

### 1.4 AI 任务按窗口分桶

- 划词翻译 / AI 续写 / 润色 / 摘要 / 对话的单任务槽**按窗口隔离**：窗口 A 发起的任务不再顶掉窗口 B 的任务；同一窗口内新任务仍自动取消旧任务（v0.6.0 语义不变）。
- 全文翻译并发槽同时记录所属窗口，取消本窗口任务不会误杀其他窗口正在跑的批次。
- 窗口关闭时清理本窗口任务槽，不留孤儿流式请求。

### 1.5 多窗口会话恢复

- 会话文件 `%APPDATA%\com.lightmd.app\session.json` 记录窗口的标签、活跃下标与打开的文件夹；**不存窗口几何**（由 `tauri-plugin-window-state` 按固定槽位 label 负责，跨会话自动复用）与**不存未保存正文**（与 v0.8.5 一致）。
- 新增显式退出动作「**退出 LightMD**」（标题栏「窗口」菜单 / 命令面板 / `Ctrl+Q`）：只记录**主窗口**（第四轮修订语义，见 §5）。
- 新增设置「**启动时恢复其他窗口**」（设置 → 通用，位于「外部文件打开方式」下方，默认**关闭**；第三轮修订语义）：
    - **关闭**（默认）：重启只恢复主窗口（主窗口的标签与打开文件夹仍按会话精确恢复），中途关掉的窗口不会复活；
    - **开启**：恢复**上次会话的全部窗口**——包括退出时逐个点击关闭的那些（「关闭最后一个窗口 = 退出应用」，此刻本会话出现过的全部窗口随快照落盘）；但用「退出 LightMD」/ `Ctrl+Q` 显式退出时不恢复其他窗口（第四轮修订）。
- **合并到主窗口的窗口不会复活**：合并时它已从会话快照中除名，其标签只会出现在主窗口里（第三轮新增）。
- 「启动载入上次文件」关闭时**不恢复任何窗口与标签**，且不残留会话文件。
- 纯单窗口会话不写会话文件，行为与 v0.8.5 一致。

### 1.6 新增快捷键

| 快捷键 | 功能 |
| --- | --- |
| `Ctrl+Shift+N` | 新建窗口 |
| `Ctrl+Shift+W` | 关闭当前窗口（`Ctrl+W` 仍是关闭标签） |
| `Ctrl+Alt+O` | 打开文件到新窗口（`Ctrl+Shift+O` 已被「切换大纲栏」占用） |
| `Ctrl+Q` | 退出 LightMD（记录完整窗口集合，供「恢复其他窗口」下次还原） |

### 1.7 设置

- 设置 → 通用新增「**外部文件打开方式**」：当前窗口（默认）/ 新窗口 / 每次询问。
- 设置 → 通用新增「**启动时恢复其他窗口**」：关闭（默认，只恢复主窗口）/ 开启（恢复全部仍存活的窗口）。

| # | 反馈现象 | 根因 | 修复 |
| --- | --- | --- | --- |
| 1 | 「在新窗口打开文档 → 关掉新窗口 → 重启后又冒出那个已关闭的窗口」 | 会话快照为满足「多窗口恢复」把**已关闭窗口**也一并记录 | 快照只记录退出时仍存活的窗口；新增「启动时恢复其他窗口」开关（默认关）+「退出 LightMD」显式退出动作 |

顺带加固：重命名/移动文件产生的「移出」事件不再被误判为删除（关闭标签前先确认文件确实不存在）。

## 三、用户反馈修复（第二轮：0.9.0 交付后复测）

> 用户在第一轮修复后的安装包上复测，发现 5 项遗留问题。逐条定位根因并修复，均补充了回归用例。

| # | 反馈现象 | 根因 | 修复 |
| --- | --- | --- | --- |
| 1 | 「多窗口版本把浏览位置记忆弄坏了：重开软件后所有标签的阅读位置都重置了」 | 窗口引导流程的 `finally` 抢在 legacy 恢复流程**之前**复位了「会话恢复期」标志；此后恢复流程打开每个文件时都走「首次打开 → 清空浏览进度」分支，把刚 `loadSnapshot()` 注入的跨会话位置逐个清掉 | 抽出纯函数 `shouldEndRestoreWindowOnBoot`：legacy 模式的复位改由「最近文件恢复」effect 的 `finally` 负责，引导流程只在非 legacy（含异常路径）复位，既保住阅读位置又不会永久卡在恢复期 |
| 2 | 「开启『启动时恢复其他窗口』后，多窗口编辑再全部关闭重开，主窗口的所有标签和文件夹都没了」 | 会话快照把 `main` 也当普通窗口剔除。最常见的退出顺序「先关主窗口 → 再关辅助窗口」会写出**没有主窗口条目**的残缺快照，下次启动主窗口空白 | Rust 侧新增 `main_state`：主窗口的最后状态始终随快照落盘（主窗口每次启动必定重建，不属于"复活已关闭窗口"；`restore_windows` 仍跳过 `main`，不会多建窗口）；`register(main)` 时清副本避免串数据 |
| 3 | 「保存后右下角仍提示 xxx 已被外部修改，保存前请确认」 | `note_file_written` 在 `std::fs::write` **返回之后**才登记 mtime，而 notify 回调线程可能抢在登记之前完成 `is_known_mtime` 判定（毫秒级调度竞态），事件被真的 emit；前端此时脏标记尚未清除 → 误判为外部修改 | 双重加固：① Rust 侧增加 `SELF_WRITE_SUPPRESS_MS`（1.5s）「刚写过」抑制窗口，与 mtime 去重并联，彻底覆盖竞态；② 前端新增 `selfWriteGuard` 内容指纹（`fileService.writeFile` 统一登记），watcher 事件到达时比对磁盘内容，一致即视为自身回声——即使事件迟到也绝不误报。另：干净标签的磁盘内容与标签一致时不再重复弹「已自动重新载入」 |
| 4 | 「落盘文件未保存时关闭窗口选『不保存』，重开软件所有标签都被关闭了」 | 选择"不保存"本身不动标签，问题出在会话落盘：关掉**最后一个**窗口时旧实现跳过落盘，磁盘上仍是上一次会话的旧数据（甚至缺主窗口条目） | 「不保存」语义保持原样（只决定已落盘编辑是否写回磁盘）；关闭最后一个窗口（= 退出应用）时**必定**重写会话，并把该窗口自身的最后状态一并写入；`finalize_session` 也改为统一走 `persist_session`。此外前端在会话快照缺主窗口条目时回退到 v0.8.5 恢复路径，避免升级用户首启空白 |
| 5 | 「设置里『启动时恢复其他窗口』的功能描述要小字号、灰色、放在按钮后面」 | 描述用的是块级 `.settings-hint`（继承正文色），因此另起一行且不是灰色 | 新增 `.settings-switch-row`（flex 行）+ `.settings-hint-inline`（12px、`--text-secondary` 灰色、跟在开关按钮后面），描述文案不变 |

第二轮顺带加固（同属问题 2/4 的完整闭环）：

1. **会话文件续命规则**：只要本会话出现过 ≥2 窗口，**或磁盘上已有上一次会话**，就继续按会话快照恢复（回访的多窗口用户即便这次只开主窗口，也不会退回"最近文件"近似恢复而丢标签）；纯单窗口用户仍走 v0.8.5 语义。
2. **只裁剪、不整份丢弃**：关闭「启动时恢复其他窗口」时改调用 `prune_session_secondaries`（只删辅助窗口条目），主窗口下次仍能精确恢复全部标签与文件夹。
3. **最后关闭的窗口随会话恢复**：关掉最后一个窗口等于退出应用，此刻"用户看到的画面"会完整落盘（关闭顺序 main → sec-N 时，辅助窗口也不会凭空少一个）。

## 四、多窗口功能优化与修复（第三轮复测反馈）

> 用户就多窗口交互提出 2 项功能优化并反馈 1 个恢复缺陷。逐条实现/定位根因并修复，均补充了回归用例。

| # | 需求/反馈 | 实现与根因 | 结果 |
| --- | --- | --- | --- |
| 1 | 「左侧栏『打开的文件』条目右键增加『在新窗口中打开』入口」 | 「打开的文件」条目的右键菜单只有"重命名/关闭/收藏"，缺一个与文件树右键对等的开新窗口入口 | 新增菜单项（`data-testid="temp-open-in-new-window"`），与文件树右键复用同一命令 `filetree.openInNewWindow`：新窗口打开该文件，本窗口标签保持不变 |
| 2a | 「鼠标左键按住标签栏标签拖拽，直接将该文档移动到新窗口」 | 标签按下启动的是文件拖拽（只支持拖到侧栏文件夹），拖到别处一律取消 | 自制拖拽新增「拖出源区域」分支：拖出**标签栏 + 左侧栏**范围松手 → 调用既有「移动到新窗口」流程（未保存的真实文件先提示；未落盘临时标签连内容迁移，且不可投放文件夹）；拖拽浮层实时显示「松开以移动到新窗口」；拖回标签栏内松手 = 取消，原语义不变 |
| 2b | 「将新窗口拖拽移动至主窗口的标签栏，提示是否合并回主窗口，确认后合并」 | Webview 无法感知其他窗口几何，此前只有菜单入口（合并到主窗口） | 新增 Rust 侧 `merge_detect` 模块：监听 `WindowEvent::Moved`，被拖窗口压住主窗口顶部（标题栏+标签栏条带，按 DPI 换算）且满足**建窗 3s 忽略期 + 窗口有焦点 + 500ms 静止去抖**三道闸门后，用当前几何复核再向该窗口发 `lightmd:mergeOffer`；前端弹「合并回主窗口？」，确认即走既有合并流程并关闭自身。防误触设计：几何恢复/程序化移动无焦点不触发，拖动路径扫过不停留不触发；**同一次驻留（压在条带上未离开）只询问一次**，点「取消」后小幅挪动不重复弹窗，拖离条带再拖回才会重新询问 |
| 3 | 「设置已开启『启动时恢复其他窗口』，多窗口后逐个点右上角关闭，重开软件后没有恢复其他窗口」 | 两个根因叠加：① 中途已关窗口的最后状态在关闭时即被丢弃，退出（关闭最后一个窗口）时的快照只剩"还活着"的窗口；② **第二轮引入的回归**——`finalize_session` 改为无条件落盘，最后一个窗口关闭后进程退出时又用「存活窗口=0」的快照**覆盖**了刚写好的退出快照 | 窗口最后状态保留至进程结束；关掉最后一个窗口（= 退出应用）时生成**完整退出快照**（本会话出现过的全部窗口、各取最后状态；空窗口剔除；已合并除名的窗口剔除）；`finalize_session` 恢复「仍有存活窗口才落盘」守卫 |

第三轮语义修订（「启动时恢复其他窗口」）：

- **开启** = 恢复**上次会话的全部窗口**（含退出时逐个关闭的）；「逐个关窗」与「`Ctrl+Q` 退出」的差别在第四轮进一步明确（见 §5）：前者把本会话全部窗口写入快照，后者只写主窗口。
- **关闭**（默认）= 只恢复主窗口，中途关掉的窗口不出现（原第一轮语义）。
- **合并到主窗口的窗口不会复活**：合并时通过新增 `forget_window_state` 命令把自身从会话「最后状态」中除名（标签已转移，原样恢复会在两个窗口重复出现同一批标签）。

本轮发布还包含用户自行提交的 Markdown 序列化往返修复（`689dcee`，B1~B6/C1~C5/D1~D11 共 22 项：保存/重载不再改坏软换行、emoji、引用与代码块边界等，附 590 行专项回归测试）。

## 五、多窗口功能优化与修复（第四轮复测反馈）

> 用户就多窗口提出 2 项功能实现/优化并反馈 1 项恢复逻辑调整。逐条定位根因并实现，均补充了回归用例（Rust 5 项几何/快照单测 + 前端 13 项）。

| # | 需求/反馈 | 根因 | 实现与结果 |
| --- | --- | --- | --- |
| 1 | 「主窗口打开了 a 文件，在**新窗口**里编辑 a 并保存后，主窗口打开的 a 文件应**立即刷新**为刚保存的内容」 | 自第二轮引入的「自身写入抑制」是**进程全局**的：`write_file` 只登记「本应用刚写过该文件」，watcher 回调据此把**所有**窗口的事件都吞掉 → 同样打开了该文件的**其他窗口**永远收不到变更通知，标签内容停在旧版本 | 抑制范围收窄到**写入窗口**：`write_file` 增加 `window: WebviewWindow` 参数，按 `(路径 → {写入窗口 label → 时刻})` 登记；事件载荷新增 `source`（写入者 label 列表），**照常广播**——写入窗口按 `source` 忽略自己的回声（仍保留前端「自身写盘内容指纹」兜底，覆盖登记晚于事件到达的调度竞态），其他窗口正常重载。mtime 去重与新语义解耦，只承担「同一变更只上报一次」的幂等职责 |
| 2 | 「拖拽**新窗口的标签**移到主窗口标签栏，松开鼠标跳出提示『是否合并到主窗口』，点是则合并，否则不合并」（第三轮只实现了拖**窗口标题栏**） | 标签拖拽全程由**源窗口**捕获鼠标，源窗口的 DOM 拿不到指针在屏幕上的位置，无法判断"松手时标签压在主窗口标签栏上" | 新增 `merge_tab_drop_target` 命令：由 Rust 读全局光标坐标（物理像素），与**其他**窗口的「标题栏+标签栏」条带（按 DPI 换算、左闭右开）做几何命中，返回落点窗口及其是否主窗口。TabBar 拖出标签栏松手时改为调用 App 新入口 `onTabDropOutside`：**落点是主窗口标签栏** → 弹既有「合并回主窗口」询问（`mergeOffer`），确认即走完整合并流程（全部标签并入主窗口并关闭本窗口）；**落在其他位置**（桌面、编辑区、非主窗口）→ 维持「移动到新窗口」，第三轮行为完全不变 |
| 3 | 「恢复逻辑调整：通过『窗口 > 退出 LightMD』或 `Ctrl+Q` 关闭的，下次重新打开软件后**不恢复窗口**」（点右上角关闭按钮的仍照常恢复） | `quit_app` 写的是「退出时刻**全部存活**窗口」的完整快照，与逐个点关闭按钮的效果不可区分，用户无法用显式退出表达"这次会话到此为止" | 显式退出改为只写**主窗口**条目：`quit_app` 置位 `quit_action` 并调用新增的 `snapshot_for_quit`（只保留主窗口最后状态；主窗口已被关闭、Primary 晋升时把当前 Primary 重标为 `main` 写入），`finalize_session` 尊重该标记、不再用存活窗口快照覆盖它。下次启动恢复主窗口的标签/文件夹/浏览进度，**其他窗口不再出现**；逐个点右上角关闭（关掉最后一个 = 自然退出）的第三轮语义原样保留。前端退出前新增 `flushWindowState`，绕过 300ms 防抖与指纹跳过立即上报，确保快照就是"退出那一刻"的标签集合 |

第四轮语义修订（「启动时恢复其他窗口」开启时）：

- **逐个点右上角关闭**（关掉最后一个窗口 = 自然退出）= 下次恢复**本次会话的全部窗口**（含此前已逐个关闭的）；
- **「窗口 > 退出 LightMD」/ `Ctrl+Q`** = 下次**只恢复主窗口**（其他窗口不出现，主窗口的标签/文件夹/浏览进度照常恢复）；
- 合并到主窗口的窗口仍然永不复活（`forget_window_state`）。

实机测试期间发现并修复的缺陷（均已补充回归用例）：

1. **定向事件跨窗口泄漏**：Tauri v2 的 `emit_to(label)` 只过滤监听器注册目标，JS 侧 `listen()` 注册目标为 `Any`，导致所有窗口都会收到本该只发给某一个窗口的事件 —— 表现为「关闭主窗口时所有窗口一起关闭」「双击一个文件时每个窗口都打开它」。已改为 `{ target, payload }` 信封 + 前端按 label 过滤。
2. **路径分隔符不一致**：Rust 事件中的路径为正斜杠，而「用原生文件对话框打开」的标签存的是反斜杠，导致 `getTabByPath` 匹配失败、外部修改/删除联动静默失效。已引入 `pathCompareKey`（分隔符 + 大小写归一）统一比较。
3. **自身写入被误判为外部修改**：见「用户反馈修复（第一轮）」第 2 条与「第二轮」第 3 条。
4. **已关闭窗口复活**：见「用户反馈修复（第一轮）」第 1 条。

## 九、升级提示

- 从 v0.8.5 / v0.9.0（第一、二轮）覆盖安装即可，无需卸载；设置、最近打开、收藏夹、临时标签全部保留。
- 若第一轮版本曾留下残缺的 `session.json`（主窗口条目缺失），第二轮版本会自动回退到最近文件恢复并在下次关闭时写回，无需手动删除。
- 第三轮起「启动时恢复其他窗口」开启时按「上次会话全部窗口」恢复（含逐个关窗退出的场景）；若你更希望"只恢复关剩下的窗口"，请使用 `Ctrl+Q` 显式退出。
- 首次使用多窗口时，建议在设置中确认「外部文件打开方式」符合习惯（默认与 v0.8.5 一致：当前窗口）。
