## 二、版本内容

本版**不新增功能**，只做缺陷收敛与一致性收口。9 项修复按严重程度排列：

### 2.1 【P0 崩溃】含 Emoji 短码的文档打不开（白屏）

**现象**：打开任何含可识别 Emoji 短码（如 `:smile:`、`:heart:`）的文档，阅读/编辑模式**直接崩溃**；同一文档在分屏模式却能正常显示，用户无法自救。

**根因（两层，均已实测确认）**：

1. `emoji-render.ts` 为 **`text` 节点**注册 NodeView 并返回 `<span>`。ProseMirror 硬性要求文本节点必须渲染为 DOM **文本节点**，否则 `create()` 直接抛 `RangeError: Text must be rendered as a DOM text node`（`prosemirror-view@1.41.8` `dist/index.cjs:1465`）。
2. 实测进一步发现：**即使改回返回文本节点也不可用** —— 自定义 spec 会让该节点变成 `CustomNodeViewDesc`，而该类**不实现 `localPosFromDOM`**，`posAtDOM` 退化为「整个文本节点只映射到一个位置」：`hello :smile: world` 的 15 个 DOM 偏移**全部**映射到 docPos=1，点哪里光标都跳到段首。且与内容长度无关（等长替换同样失效）。

**修复**：整条 text NodeView 路线放弃，改用 **Decoration**（与既有的 `inline-mark-reveal` 同机制）：

- 短码区间加 `Decoration.inline` + `data-emoji` 属性；原短码文字用 `font-size:0` 收起，`::before` 叠加显示图形；
- **DOM 文本长度与 doc 完全一致** → `posAtDOM` / `coordsAtPos` / 选区全部正常；
- doc 与序列化零变化（阅读模式看图形，存盘仍是 `:smile:`，复制也是 `:smile:`）。

**加固**：`createEditor` 增加 try/catch（失败时退化为「无自定义 NodeView」的简化视图），`main.tsx` 挂载应用级 `ErrorBoundary` —— 任何未预期的渲染错误都给出**可重试、可复制详情**的提示页，而不是白屏。

### 2.2 【数据丢失】图片 `![alt|300](src)` 宽度被静默抹除

**现象**：设置过宽度的图片，在分屏预览或任一导出执行过一次之后，阅读模式里宽度失效；此时若编辑该段落，**存盘即永久丢失 `|300`**。

**根因**：`renderPipeline.ts` 的 `getRenderMarkdownIt` 返回的是 `parser.ts` 的**模块级单例 `md`** —— 与编辑器 PM 解析用的**同一个实例**。而 `imageSizePlugin` 的 core rule 会在**每次 parse** 时就地改写 `token.content`（`"alt|300"` → `"alt"`），于是污染是持久的：此后 PM 解析读到的已是去后缀的内容，`width` 变 `null`。因 serializer 有「原文切片快路径」，未编辑的块存盘时仍能保住原文 —— 这正是该缺陷长期未被发现的原因（一编辑就暴露）。

**修复**：渲染管线改用**独立实例**（`createMarkdownIt` 新建 + 装插件，按 GFM/CommonMark 各缓存一份），与 PM 解析彻底隔离；配置仍来自同一工厂，R1 的「统一配置源」目标不受影响。

### 2.3 【已回退】段内换行的回车语义变更与续行转义

**本版曾做的两处改动，经实机验证观感不达预期，已整体回退**，恢复到 v0.12.1 之前的行为：

| 改动 | 内容 | 回退原因 |
|---|---|---|
| 回车语义 | 顶层普通段落内 `Enter` 改为插入段内硬换行（`Shift+Enter` 改为新建段落） | 阅读模式行距变大，且切换编辑/分屏后仍出现空行，未解决原始反馈 |
| 续行转义 | 段内硬换行后的续行行首按 21 类危险构造插 `\`，避免被块级规则劫持 | 上述回车语义已回退，该机制失去存在场景 |

**当前行为（与 0.12.1 之前一致）**：

- `Enter` = **新建段落**；`Shift+Enter` = **段内硬换行**（Markdown 两空格换行）
- 列表 / 任务项 / 引用 / 标题 / 表格内语义不变
- 段内硬换行后紧跟 `---`/`===`/`- `/`# ` 等行首语法时，仍会被 Markdown 块级规则解释（这是 Markdown 的固有语义，非编辑器缺陷）——需要真正的标题/列表/引用时请先按 `Enter` 新建段落

### 2.4 跨块选区回车不再合并段落

原实现没有空选区守卫，而 `replaceSelectionWith` 会先删除整个选区 —— 选中跨两个段落的文字后按回车，两段会被合并成一段、其余内容被删除。现补 `selection.empty` 守卫（与 `insertHardBreak` 口径一致），非空选区交回 `splitBlock`。

### 2.5 消除反斜杠噪音（`$` 与 `==`）

`价格 $100` 不再存成 `价格 \$100`、`a == b` 不再存成 `a \=\= b`。改为与已修的 `~`/`^` 同口径的**真实配对判定**（本机实测 markdown-it）：

- `$`：两个 `$` 且中间至少一个字符才配对 → 单个金额符号不转义，`x$y$z` 这类真配对仍转义；
- `==`：闭合 `==` 的两侧内容必须非空白且非 `=` → `a == b`、`2 == 3 == 4` 不转义，`a==b==c`、`==x==` 仍转义。

> 此前 `==` 的转义写在两处，其中一处在本次 P5 修复时被遗漏，已一并清理。

### 2.6 改标题后锚点/目录失配

`id` 只在**解析时**写入一次，此后阅读模式改标题文本**没有任何机制重算**；而 `[toc]` 的 `collectHeadings` 是按**当前文本**重算 slug 的 → 正文标题仍是 `id="old-title"`，目录却生成 `href="#new-title"`，点击跳转失败。

**修复**：新增 `heading-id-sync` 插件（appendTransaction，O(标题数)），docChanged 时按**与解析期同一 slugify + 去重口径**重算每个标题的 `id`（首次不加后缀、第 2 次 `-1`、第 3 次 `-2`…）；id 已一致时不产生任何事务。

### 2.7 分屏右侧被双重缩放 / 不铺满分栏

分屏 iframe 复用了 `.ProseMirror` 类（为拿到字号/字体变量），但该类还带两条**只对编辑器正文元素成立**的规则：

- `zoom: var(--doc-zoom)` → iframe **元素自身**被缩放，与 iframe 内部 `body` 的 zoom **叠乘**（200% 时右侧实际约 400%，溢出被 `overflow:hidden` 裁掉）；
- `max-width: 860px; margin: 0 auto` → iframe 被钳制居中，**覆盖**内联的 `width: calc(50% - 3px)`，不铺满分栏。

**修复**：新增 `iframe.split-preview { zoom: 1; max-width: none; margin: 0; padding: 0 }` —— 缩放与内容宽度只由 iframe **内部**文档负责。（该缺陷自 v0.2.0 引入类名复用起即存在，v0.12.0 的缩放功能让它以更严重的形式暴露。）

### 2.8 焦点保持三模式一致

用户反馈「缩放窗口保持阅读焦点」有偏差。定位到两处：

**① 分屏右侧完全不参与排版锚点补偿。** `captureTypographyAnchor` 只处理「阅读模式的阅读容器」与「编辑/分屏左侧 textarea」，**分屏右侧 iframe 缺失** → 在设置里拖行高/段间距/内容区宽度时，右侧预览的阅读焦点丢失（左中右三模式行为不一致）。

**修复**：把 iframe 文档滚动元素接入同一套块锚点（`captureAnchor(scroller, "body > *")`），与既有 iframe 的宽度锚点效应同口径。

**② 分屏下状态栏阅读进度恒显 100%。** 进度上报只监听 `editorRef.current`（PM 阅读容器），而该容器在 split 模式是 `display:none` → `scrollHeight - clientHeight = 0` → 判定为"无可滚动空间" → 恒报 100%。分屏实际滚动发生在左侧 textarea 与右侧 iframe。

**修复**：按模式选择真实滚动容器（阅读 → editor-container；编辑/分屏 → textarea），并在模式切换时重新绑定。

### 2.9 导出样式跟随应用设置

`EXPORT_CSS` 是模块级常量，字号/行高/内容宽度**全部硬编码**（16px / 1.8 / 860px）。用户在设置里调完排版，导出结果完全不变 —— 属「所见非所得」（主题明暗此前已跟随，唯独排版三项没有）。

**修复**：改为工厂函数 `buildExportCss(t?: ExportTypography)`，从设置读取**字号 / 行高 / 段间距 / 内容宽度 / 字体**，与阅读区 `.ProseMirror` 同口径（段间距按 `0.8em × 倍数` 乘算）；未设置时回落原默认值，**不改变既有导出观感**。HTML / PDF / PNG 三处全部改走该函数，PNG 的截图容器宽度也随之跟随内容区宽度。

顺带修正 `includeCSS` 的**注释与实现不符**（注释称「不再无条件注入 printCss」，但 `printCss` 位于三元之外、实际恒注入），并把口径明确为：**`@page`（纸张/页边距）与页眉页脚属分页结构性、恒注入；`includeCSS` 只控制内容排版**（及 body 基础样式）。

### 2.10 i18n 收口

表格工具栏「表头行不可删除」禁用提示、Mermaid 空图表提示与语法错误提示补全英文（此前硬编码中文，英文界面穿帮）。

## 四、已知范围

- **P4（`pairTabOut` 在表格单元格内抢占 Tab）按需求未处理** —— 经确认这是用户期望的行为（配对符号内按 Tab 跳出配对）。
- **回车语义已回退**：v0.12.1 需求10 的「回车 = 段内换行 / `Shift+回车` = 新建段落」及其配套的续行行首转义，在本版经实机验证后**整体回退**（观感不达预期），恢复 `Enter` = 新建段落、`Shift+Enter` = 段内硬换行。详见 §2.3。
- **导出样式定制**：PDF 有页眉/页脚/边距等选项；**DOCX / EPUB / LaTeX 仍无样式定制入口**（属未实现功能，非缺陷）。
- HTML 导出的 mermaid 走旁置 `_assets/mermaid.min.js`，**单文件 .html 不自包含**（需连同目录一起拷贝）；资源读取失败时仍会回退 CDN 并给出告警。
- 尚未支持（详见 README 清单）：跨文件全文搜索、标签、frontmatter、双链/反链/图谱、书签、Git 集成、合并单元格等。

## 五、升级说明

- **直接覆盖安装即可**，无破坏性变更；设置、快捷键、收藏、最近打开、会话（含未保存标签）等本地数据全部保留。
- **如果你曾在文档里用过 Emoji 短码**：此前这些文档在阅读/编辑模式无法打开（白屏），本版修复；显示为图形、存盘仍是短码，行为与分屏/导出一致。
- **如果你的文档中有设置过宽度的图片**：本版修复了「宽度被静默抹除」的问题；此前已因编辑而丢失 `|300` 的图片需要手动补回宽度（可在图片编辑对话框里设置）。
- **在段内换行后写块级语法**：`Shift+Enter` 段内硬换行后紧跟 `---`/`- `/`# ` 等行首语法时，仍会按 Markdown 块级规则被解释成标题/列表/引用（0.12.1 之前的既有行为，本版曾加的自动转义已回退）。若你本意是标题/列表/引用，请先按 `Enter` 新建段落再输入。
