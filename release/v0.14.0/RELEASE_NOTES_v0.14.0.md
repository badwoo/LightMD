## 二、需求 1：三模式合并为二模式

### 2.1 菜单只剩「阅读 / 编辑」

- 标题栏模式按钮组由「阅读 / 编辑 / 分屏」收敛为**两格**：阅读、编辑。
- **点「编辑」直接进入原「分屏」观感**（左源码 + 右预览），不再有独立的「分屏」入口。
- 双击 `Ctrl`：阅读 ↔ 编辑（进入编辑时右侧预览自动打开）。
- 双击 `Shift`：
  - 在阅读模式 → 进入编辑并展开右侧预览；
  - 已在编辑模式 → 纯切换右侧预览（等同下面的「关闭预览 / 打开预览」）。
- 命令面板里原「分屏模式」改为「切换预览面板（编辑模式）」（命令总数不变）。

### 2.2 分割线上的竖排呼吸小字

- 鼠标移到**右屏**（或分割条）时，分割线正中浮现一列**灰色竖排**小字「关闭预览」：
  - `writing-mode: vertical-rl` + `text-orientation: upright`，11px、字距 2px；
  - 带 2.4s `ease-in-out` 的呼吸动画（透明度 0.55 ↔ 1.0）；
  - 平时不可见（`opacity: 0`），符合「隐约出现」的诉求。
- 点「关闭预览」→ 右屏**顺滑往右滑到语法辅助栏左侧**（宽度 `(1-比例)` → 0，280ms 缓动），
  源码区同时铺满整区；文字变成「打开预览」。
- 点「打开预览」→ 右屏**从右往左顺滑滑出**，恢复分屏样子。
- 预览关闭后，编辑区右缘保留一条 18px 的静默窄 rail（常驻半透明「打开预览」竖排字），
  它是重新打开预览的入口，也是「右屏滑到语法辅助栏左侧」的视觉落点。

### 2.3 行为细节

- `Esc` / 切标签 / 切阅读模式都不会改变「预览开关」的记忆：下次进入编辑按上次状态展开。
- 大文件（>5MB）降级为编辑模式时**自动关闭预览**（与旧版「强制纯源码」等价，避免渲染超大 HTML 卡顿）。
- 无 markdown 内容时预览区自动清空（不会残留上一个文档的 HTML）。

## 三、需求 2：搜索增强

### 3.1 四个勾选项（默认全部不勾）

| 勾选项 | 语义 |
|---|---|
| **全词匹配** | 按 Unicode 词边界（`\p{L}\p{N}_`）判定：`cat` 不匹配 `concat` / `cats`，中文「测试」不匹配「我的测试」 |
| **匹配大小写** | 区分 `cat` / `Cat` / `CAT` |
| **选取范围内** | 只在**勾选瞬间的选区**内查找与替换 |
| **正则** | 沿用旧行为，替换支持 `$1` / `$&` 捕获组；非法表达式红字提示不崩溃 |

「选取范围内」的三条硬约定：

1. 选区在**勾选那一刻**捕获一次（之后手动改光标不跟随，这是确认过的语义）；
2. **替换后范围随文本增量自动平移** —— 范围不会被第一次替换撑破；
3. 勾了但**当前没有选区** → 匹配数显示 0 并红字提示「请先在编辑器中选中一段文本」，
   **绝不静默退回全文搜索**（否则一次「全部替换」会改掉整篇文档，不可逆）。
4. 切标签 / 切模式后旧选区快照作废并提示重新选取（避免跨文档错位改写）。

### 3.2 查找所有打开文件

- 点「查找所有打开文件」→ 搜索框下方展开结果条幅，每条为「**文件名 + 命中行内容**」，
  行内的关键字用 `<mark>` 高亮；同一条里多处命中全部高亮。
- 条幅顶部有汇总：`{命中数} 处（{文件数} 个文件）`。
- **点击条目跳到对应文件的对应位置**：当前文档就地定位并高亮；其他文件先切标签，
  文档就绪后按「第 N 次出现」定位（源码空间与渲染空间行号不同，用出现次序换算），
  跳不到时给出可见提示而不是「点了没反应」。
- 上限：单文件 500 行、最多 200 个文件，超出显示「结果过多，仅显示前 N 条」。
- 勾了「选取范围内」时，条幅**只列当前文档**的结果（选区是当前文档的文本坐标，
  套到别的文件上毫无意义且会把结果全误杀）。

### 3.3 两种模式都生效

- 编辑模式走源码文本，阅读模式走 ProseMirror 渲染文本，高亮与替换都是各自坐标系里的精确位置。
- 阅读模式跨段落选区：落在块间隙的位置会收敛到前一块末尾（换行符上的匹配不计入）。

## 四、需求 3：分屏分割线可以来回拖

### 4.1 缺陷与根因（真实 WebView2 实测取证）

用户反馈「往左拖拽调整大小后没法往右拖回来」。探针（`scripts/v0140-probe-split-divider.mjs`，旧版 exe + 真实鼠标手势）：

| 手势 | 发出的 mouseMoved | 父文档收到 | ratio |
|---|---|---|---|
| 往左拖 | 6 | **6** | 0.424 → 0.305 |
| 往右拖 | 6 | **0** | 冻结在 0.305 |

`document.elementFromPoint` 每一步都返回 `IFRAME.split-preview` —— 分割条右侧紧贴右侧预览 iframe，
指针一进入 iframe，父文档的 `mousemove` / `mouseup` 全部丢失，拖拽链路中断；`mouseup` 丢失还让
`body` 卡在 `col-resize` / `user-select:none`。

### 4.2 修复

- 按下时用 `setPointerCapture` 把指针捕获到分割条 → 进入 iframe 后事件仍能回到拖拽逻辑；
- 拖拽期间临时屏蔽页面内 `iframe/embed/object` 的 `pointer-events`（结束时恢复**原值**，不是清空），
  并注入一条只在拖拽期生效的运行期样式表，覆盖「拖拽中新挂载的 iframe」；
- 新增 `pointermove/pointerup/pointercancel` 通道，保留 `mousemove/mouseup` 兼容路径，
  两条通道用一个 `pointerSeenRef` 去重（保证一次手势只触发一次 `setWidth`）；
- 修掉一个潜在缺陷：`initialRatio` 原来只在挂载时读一次，外部比例变化后第二次拖拽的起点是旧值 →
  现在外部值变化会同步内部 ratio，但**拖拽进行中不覆盖**（防跟手抖动）；
- 四个方向（侧栏 / 大纲 / 分屏比例 / 竖向分节）的拖拽**数学一行未改**，`v0.8.2` 的
  「按键全松 → 立即结束」与「窗口失焦 → 结束」兜底语义保留。

### 4.3 顺带修掉的实机缺陷

「关闭预览 / 打开预览」竖排小字**点击无反应**。根因：它是分割条的**子元素**，
在分割条上启动拖拽后 `setPointerCapture` 把指针捕获到分割条，随后的 `click` 被重定向，
按钮的 `onClick` 永不触发。修复：分割条的 `onMouseDown` 对落在竖排按钮上的按下直接放行。
修复后实测：点一下右屏 1071px → 0px、文案变「打开预览」，再点回到 1071px。

## 二、7 条需求逐条落地

### 需求1：增加更新功能（设置里最后）

- 设置面板**末尾**新增「软件更新」区：当前版本 + 「检查更新」按钮。
- 有新版本 → 显示 `发现新版本 vX（当前 vY）` + 可折叠「更新说明」+ 「下载并安装」+ 「打开发布页」。
- 下载中显示百分比进度条 → 完成后提示并**启动安装向导**。
- 已最新 → 「已是最新版本 v0.14.0」。
- 失败 → 「检查更新失败：<原因>」+「重试」，不卡界面。

技术要点（为什么这么做）：
- **网络请求必须走 Rust**：`tauri.conf.json` 的 CSP `connect-src` 不含 https，WebView 无法直连
  GitHub；Rust 侧用 `reqwest`（已有依赖）+ 20s 超时 + 必带 `User-Agent`（无 UA GitHub 返回 403）。
- **版本比较按数字段**而非字符串：字典序会误判 `"0.9.0" > "0.14.0"`。
- **下载目录**：`app_cache_dir()/updates/`，流式写盘（大文件不占内存），期间 emit
  `lightmd://update-progress`；失败清理半成品。
- **安全**：`launch_installer` 三重校验——路径必须存在、扩展名只能 `.exe`/`.msi`、
  canonicalize 后必须在 `updates/` 目录内（按路径组件判定，`/updates-evil` 不能绕过）。
  绝不执行网络返回的任意可执行文件；`asset_url` 只用于下载。
- 安装包筛选排除 `.sig` / `SHA256SUMS` 这类非安装文件。

### 需求2：阅读 ↔ 编辑来回切换丢失阅读进度

- 实测取证（CDP 采样）：阅读 50% → 点「编辑」→ 右屏 iframe **0.006**、左栏 textarea **0**。
- 根因两层：
  1. `applyScroll` 的双 rAF 在 ~44ms 执行，此时左栏还不可滚动 → 旧代码
     `scrollTop = newTop ?? 0` **当场写 0 且不重试**；`splitScrollSync` 随即把这个 0
     推给右屏 → 两屏都掉 0。
  2. 右屏的待恢复值只在「iframe 内容写入 effect」里被消费，而该 effect 的依赖是
     `previewHtml` —— 阅读→编辑切换时它**根本没变**（右屏内容早渲染好了，只是外壳
     宽度从 0 变正）→ effect 不重跑 → pending 永远没人消费。
- 修法：
  - 新增纯函数 `planScrollRestore(percent, scrollHeight, clientHeight, attempt)`：
    **永不在"容器不可滚动"时写 0**；期望非顶部则按 60ms × 最多 24 次重试
    （覆盖 mermaid/katex 异步撑高的场景）。
  - 右屏独立走 `restorePendingIframeScroll()`，与内容写入 effect 的消费互为双保险。
- 实测：50% → 编辑（左 0.50 / 右 0.52）→ 回阅读 0.50。

### 需求3：关闭文档重新打开进度被重置

- 删掉 `App.tsx` 里 4 处「关闭 / 重新打开即清进度」的 `fileScrollProgress.clear(...)`
  （v0.7.0 旧语义，与本次诉求相反）；另有一处「标签迁移到新窗口」也一并按同口径处理。
- 保留：`clearAll()`（关闭"启动载入上次文件"开关 / 会话恢复失败时仍要清）、
  `clearOutlineScroll` / `forgetDocHistory`（大纲位置与撤销历史跨关闭保留有位置敏感风险）。
- 实测：关闭前 0.62 → 重新打开 0.62。
- 取舍：进度留在**当前会话内存**，所以同一会话内关闭→重开可恢复；关闭后该键不再出现在
  快照的 keys 里 → 重启应用不恢复已关闭文件（快照语义仍保持"打开标签的进度"）。

### 需求4：查找到多文件后替换，应替换所有文件

- 新增 `applyFileText(fileKey, newText)` 写回通道 + `replaceAllAcrossFiles()`：
  - 对每个文件**按自身文本重算命中**（不复用条幅的行内偏移快照）；
  - 逆序拼接避免偏移漂移；CRLF 用 `buildRawOffsetMap` 换算回原文坐标；
  - 与查找共用同一 `SearchOptions`（全词/大小写/正则/范围）；
  - 当前文档走编辑区写回（与既有「全部替换」同一条路径），其他标签写 store
    **并置脏**（否则关窗口不提示保存 → 用户以为改成功、磁盘还是旧的）；
  - 勾了「选取范围内」时其他文件跳过（选区只有当前文档有坐标）。
- 条幅展开时按钮文案改为「全部替换（所有文件）」；完成后提示「已替换 N 个文件」。
- 条幅收起时保持旧的「只替换当前文档」语义，避免误改未展示的文件。
- 实测：条幅列出 A+B 两个文件 4 处命中 → 替换后「已替换 2 个文件」→ 两个标签都置脏
  → 切到 B 内容确实变成 DOG（2 处）。

### 需求5：搜索要跨文档生效（切文档后立即在新文档搜索）

- 新增 `contentVersion` prop（宿主传 `forceUpdateKey`）+ 换文档重搜 effect。
- 为什么必须显式监听：阅读模式下换文档时 `editorView` 是**同一对象**、`sourceContent`
  在阅读模式也不变 → `performSearch` 的依赖全都没变，effect 不会重跑 → 搜索永远停在旧文档。
- 实机验收又抓到一个更隐蔽的 bug：换文档瞬间文本还是旧的，此刻排的定时器捕获了**旧闭包**；
  等文本更新后 `performSearch` 换了身份，但 effect 依赖没变 → 不重跑也不 cleanup →
  旧定时器照常触发，把刚算对的结果**覆盖回"无结果"**。
  修法：`performSearchRef` 永远用最新闭包 + 世代序号丢弃迟到回调。
- 实测：A 搜「李四」无结果 → 不关面板切到含「李四」的文档 → 立即 `1/1`。

### 需求6：竖排小字改艺术字体 / 颜色更浅 / 呼吸带金属光泽（性能优先）

- **字体**：系统自带衬线字体栈（Palatino Linotype / Book Antiqua / Georgia →
  华文中宋 / 宋体 / Noto Serif CJK → serif）。**不引任何字体文件**：离线无网络、
  中文艺术字体动辄数 MB、还会带来首屏字体加载抖动。
- **颜色**：`color-mix(in srgb, var(--text-tertiary) 72%, transparent)`，明显更浅。
- **金属光泽**：**静态** 7 段银色渐变（银灰→亮银→银灰→高光→银灰）+ `background-clip: text`；
  呼吸动画**只动 `opacity` 与 `transform`**，光泽的"流动感"来自"渐变静止、透明度在动"。
- **性能实测**（headless Edge 155 = WebView2 内核，CDP `Performance.getMetrics` 采 3 秒）：

  | 实现 | LayoutCount | RecalcStyleCount | TaskDuration |
  |---|---|---|---|
  | 本版（静态渐变 + opacity/transform） | **0** | **1** | **3.4ms** |
  | 旧版（纯 opacity） | 0 | 1 | 3.8ms |
  | 反面教材（动画 `background-position`） | 0 | **180（每帧一次样式重算）** | 93.6ms |

- `prefers-reduced-motion` 时停动画但**文字仍可见**；`.app-blurred` 时暂停动画。
- 两个实测踩掉的坑（已写进代码注释与测试，防回归）：
  1. 药丸底**不能**用 `::before` + `z-index:-1`（`background-clip:text` 下字形是元素自身
     背景，伪元素会盖住渐变，对比度 3:1 → 1.3:1）；改多层 background + `padding-box`。
  2. `text-shadow` + `background-clip:text` 在本引擎会**吃掉字形**（墨迹像素 8000→240，
     单深色阴影直接 0）→ 放弃该"可选加分"项。

### 需求7：表格拖拽改行高/列宽，重开失效

- 根因：尺寸只写在 PM 节点 attrs，GFM 管道表格语法无法表达 → 序列化即丢弃 → 重开为 null。
- 方案：**旁路注释指令**，写在表格**后空一行**（紧贴表格下一行会被 GFM 当数据行，
  实测会让表格凭空多一行、指令进单元格）：

  ```markdown
  | A | B |
  | --- | --- |
  | 1 | 2 |

  <!-- lightmd-table-size: {"columnWidths":[120,240],"rowHeights":[40,40,60]} -->
  ```

- 无尺寸时**一个字节都不加**（纯管道表格零 diff，v0.9.0 B6 契约保持）。
- parser 读回写入 attrs 并**整段吞掉**指令行（正文里没有这行）；坏 JSON / 键名不对 /
  值不是数组 → 静默忽略，表格照常解析。
- B6 原文切片：把表格块的原文区间**扩展到覆盖指令行** → 未编辑表格切片自带指令；
  被拖拽改过尺寸的是新节点 → 走逐块路径按当前 attrs 重新输出。两条路径都恰好一份，不丢不重。
- 输出前按**实际列/行数**归一化（超长截断、不足补 列100/行30）：不归一化会不收敛
  （第一次写 3 个、读回补成 2 个、第二次写 2 个 → 每次保存都改写文件）。
- 顺带修复：列表内的表格，`listToMarkdown` 原本丢掉续行空行 → 指令被贴回表格尾部。
- 实测：拖拽列表头 246px → 316px → 存盘含 `{"columnWidths":[316,176,246]}` →
  关闭重开 → 单元格内联宽度仍 316px、源码仍有指令。

实机定位到**两层**根因（`scripts/v0140-probe-req1-crossfile-preview.mjs`，T1/T2/T3）：

1. 条幅**展开**时点「全部替换（所有文件）」→ `replaceAllAcrossFiles` 对**当前文档**

2. 更糟：下一次切模式会用 PM 内容反序列化回写，**把替换结果冲掉**

修法：新增**统一写回入口** `writeBackCurrentDoc(newText)`，按视图模式分流：
- **阅读模式 + md** → dispatch `replaceWith(0, size, newDoc)` 事务（阅读视图立即更新），

两个调用方（面板自己的替换、跨文件替换的当前文档写回）都归口到它。

实测：T1-a 阅读视图立即变 PASS；T2 切编辑后源码仍是 `DOG` PASS；T3 对照组 PASS。

### 需求2：搜索替换进撤销栈；跨文件替换后切过去也能撤销/恢复

修法：`services/docHistoryStore.ts` 新增按文档键的**整篇文本级**记录：
- `recordCrossFileEdit(key, before, after)`：未激活标签写回时登记；
  同一文档连续替换**合并**为「最早的 before + 最新的 after」（用户心智是
  "撤回那轮批量替换"，不是逐处撤）；
- `doLocalUndo` / `doLocalRedo` **先**消费它，再落回常规 PM/diff 撤销栈；
- **位置敏感护栏**：只有当前文本仍与记录逐字节一致才应用，否则**丢弃记录**

- 源码态替换通道（`onSourceContentChange`）补 `recordUndoEntry`，编辑模式下也能 Ctrl+Z。

### 需求3：最近打开点时钟不出面板

1. **渲染条件口径不一致**：`RecentFiles` 自 v0.8.5 需求8 起是「文件+文件夹」混排、

2. **面板挂在滚动视口之外**：侧栏溢出时面板已挂载、高 200px、16 条数据全渲染，

### 需求4：文件夹栏只有 7 个条目 → 11 条 + 末尾留空

export const FOLDER_HEADER_HEIGHT = 32;                 // 实测值
export const DEFAULT_FOLDER_SECTION_HEIGHT =

### 需求6：标题栏菜单被编辑区挡住

**真根因不是"缺个 z-index"**，而是 stacking context **三层**失效：
1. `.titlebar` 是 `position:relative; z-index:auto` → **不创建 SC**，与后出现的
   `.app-shell`/编辑区同处 `<body>` 根上下文，按 DOM 顺序**被后绘制的编辑区覆盖**；
2. 下拉菜单自己的 `z-index:1000` **救不了** —— 它被 `.titlebar-left{z-index:1}`
   夹在那个 z-index=1 的小 SC 里（z-index 只在最近 SC 内比较）；
3. 新开软件时编辑区盖着 `.editor-empty-state`（absolute / `z-index:10` /
   整块不透明白底 / `pointer-events:none`），画在菜单之上把下探那截吃掉。

> **⚠️ 取证陷阱（非常重要）**：`elementFromPoint` 全程报"35/35 命中菜单项"——
> **假阳性**。因为它跳过 `pointer-events:none` 的层：指针确实穿得过白底，
> 但白底**照样画在菜单上面**。必须用**像素 diff** 才能证伪。

修法：`.titlebar` 加 `z-index: var(--z-titlebar, 100)` + `overflow: visible`；
`:root` 新增 `--z-titlebar: 100`（低于弹窗 1000/1100/1200、Toast 10000）。
**不给** `.app-shell` / `.app-sidebar` / `.app-outline` / `.editor-main-area` 加 z-index
—— 那会创建 SC，把内部 `position:fixed` 弹层（搜索面板等）关进低上下文，反被标题栏压住。
未改 DOM/JSX，**未用 `position:fixed`**。

A/B 实机对照（同 exe，仅切 `.titlebar` 的 z-index）：
- 修复前：菜单内文字暗色像素 = **0**（完全看不见）；隐藏空状态后像素变化
  **17243/221520 (7.8%)** → 空状态画在菜单之上。
- 修复后：文字暗色像素 = **3425**（完整可读）；隐藏空状态后变化 **0** → 空状态在菜单之下。

**真正根因：撤销有两条入口，只有一条认跨文件替换记录。**
- 菜单 / 右键 / 命令面板 → 命令总线 → App `edit.undo` → store `undoHandler`
  → `EditorContainer.doLocalUndo`（会先消费 `docHistoryStore.crossFileUndo`）；
- **阅读模式键盘 `Ctrl+Z`** → `core/keymap.ts` 的 `dynamicShortcutsPlugin` →
  直接调 `prosemirror-history` 的 `undo`（**不认记录**）。B 的 PM 历史在换文档时
  被 `resetHistory` 按内容重建（空栈）→ 键盘撤销毫无反应；A 的替换本身进了 PM 历史，
  所以表现为「只有 A 能撤」。上一轮探针走的是命令总线，因此全 PASS、漏掉了键盘入口。
- **第二个断点**：点完 B 标签后焦点在标签按钮上，App 窗口监听在
  `target.tagName !== "TEXTAREA"` 处直接 return，PM 又没焦点 → `Ctrl+Z` 完全无人处理
  （用户「点击到 B 点击撤销」的真实动作链）。

**修法**：
- PM 键位表的 `edit.undo/edit.redo/edit.redo2` 改为「有宿主转交宿主、无宿主退化为原生
  history」：`EditorContainer` 挂载时 `setHostUndoRedo({ undo: handleUndo, redo: handleRedo })`，
  阅读模式键盘撤销与菜单/右键/命令面板走**同一条入口**（含跨文件记录消费与逐字节安全护栏）；
  独立 `createEditor`（单测）无宿主时行为不变。
- App 全局 keydown 把 `global-editor` 键位按焦点分四类**互斥**处理：
  `.ProseMirror` 内让行给 PM；输入控件（搜索框等）让行给原生撤销；标签/工具栏/空白区
  交给宿主处理器；textarea 走源码撤销栈。一次按键只可能撤销一步（防双撤销）。

**实机验收（真实内容：CRLF + 末尾无换行 + 列表 + 表格 + 行内代码）8/8 PASS**：
S0 简单文档/命令总线/用户顺序（对照）· S1 真实内容/命令总线 · S2 真实键盘 `Ctrl+Z` +
TabBar + 先 A 后 B · S3 源码模式键盘 · S5 不先撤 A 直接切 B · S6 左侧文件树点击 ·
S7 **焦点在标签按钮（不点进正文）直接 `Ctrl+Z`**；S4 搜索结果条幅在替换后已无命中
（自动收起，无法点击，回退为标签点击）。全部场景均确认跨文件替换**不自动写盘**
（B 磁盘仍为原文）。

**实机时序验收（A~E 全 PASS）**：长帧 >50ms = **0**（各场景最长 18~22ms）、longtask 合计
**0ms**、总量回弹 **0** / 反转 **0** / 凹 **0px**、clientWidth **恒为 252**（254→252 抖动消失）、
wrapper 无内联高度（371ms 的 204→720 跳变消失）、scrollTop 改写 **0~1 次**、
溢出态面板**完整可见**。唯一 INFO：300ms 过渡期内有 17 帧内容比容器高 → 右侧 2px 滚动条
出现即消失，但因槽位已预留，**clientWidth 恒定、无任何布局位移**（消除它需"先算终态高度再挂载"

## 需求 1：点「检查更新」报「无法连接 GitHub」

**症状**：设置 → 软件更新 → 检查更新，报
`检查更新失败：无法连接 GitHub（请检查网络或代理）：error sending request for url (https://api.github.com/...)`。
用户预期：能正常检查；若确实没有新版本，应显示「已是最新版本」。

**根因（TLS / 代理配置，不在业务层）**
- `reqwest` 原先 features 用 `rustls-tls`（≡ `rustls-tls-webpki-roots`）：只信任**编译进二进制的
  Mozilla 根证书**，**不读 Windows 证书库**；
- 同时 `default-features = false` 把 default 里的 `system-proxy` 也关掉了 → **完全忽略系统代理**。
- 本机 GitHub 被本地 FastGithub 代理 MITM：hosts/DNS 把 `api.github.com` 指到 `127.0.0.1:443`，
  TLS 用自签 CA「CN=FastGithub」（该 CA **已装入 Windows 根证书库**）→ webpki 内置根不认它，必然失败。
- 实测三方对照：`curl -sk` 通（跳过校验）、PowerShell `Invoke-WebRequest` 通（走 Schannel + 系统库）、
  node `tls.connect` 报 `UNABLE_TO_VERIFY_LEAF_SIGNATURE`（与 webpki 行为一致）。

**修复**
1. `reqwest` features 改为 `rustls-tls-native-roots` + `system-proxy`（走系统证书库/Schannel），
   并**移除 `rustls-tls`** 避免 webpki 与 native 两套根共存产生来源歧义（`Cargo.lock` 中 `webpki-roots` 已归零）。
2. **错误分层**：Rust 侧把网络层失败（连接/DNS/TLS/超时）编码为
   `LIGHTMD_UPDATE_NETWORK|<scope>|<detail>`；前端 `parseUpdateFailure` 解析后抛 `UpdateNetworkError`，
   UI 进入独立 `offline` 态显示「暂时无法检查更新（网络不可用），请检查网络或代理后重试」，
   **绝不再谎报「已是最新版本」**。HTTP 403/404 等业务失败仍走原文案 + 重试。

**实机验证**（新 exe，FastGithub 仍在运行、MITM CA 仍在证书库）：终态 `uptodate`，文案「已是最新版本 v0.14.0」。

## 需求 2：搜索/替换后按 Ctrl+Z 撤销，搜索框失效

**症状**：搜索到内容并替换，按 `Ctrl+Z` 撤销后内容确实恢复了，但搜索框失效（匹配数/定位/高亮不再跟随）。

**根因（两个独立失效点）**
1. **阅读模式**：`performSearch` 的依赖是
   `[searchText, searchOptions, isSourceMode, sourceContent, editorView, isMdFile, viewMode]`，
   而替换走 PM 事务、撤销走 PM history —— 两者都**只改 `editorView.state.doc`**，
   `editorView` 对象不变、`sourceContent` 在阅读模式不同步 → 依赖一个都没变 → effect 不重跑 →
   `matchesRef`/`offsetMapRef` 冻结在旧 doc 坐标（匹配数停在替换后的值、高亮 Decoration 被映射到**错位**的词、
   上下跳转失效）。实测 `cat dog cat` 搜 `cat` → 替换 → 撤销：全程停在 1/1（应回到 1/2）。
2. **两种模式共用**：替换后 50ms 的 `setTimeout(() => performSearch(), 50)` 捕获**旧闭包** ——
   源码模式实测 +20ms 算出正确的 1/1，+60ms 被旧 `sourceContent` 覆盖回 1/2 并永久保持。

**修复**（仅 `SearchReplace.tsx`，未动宿主）
- `MutationObserver` 观察 PM DOM + **doc 对象身份闸门**（自身高亮事务只改 meta 不改 doc，不会自激成环）；
  **不包 `dispatch`**，因为 `Outline.tsx` 已在包且卸载时还原，两处互相覆盖会让监听静默丢失。
- **150ms 短防抖**（连续打字不每帧全量重扫）；替换类离散操作走 `runContentResync()` 立即重算。
- 三处延迟重搜收口到 `performSearchRef.current()`。
- 搜索词与四个勾选项在撤销后**完整保留**（不重建面板、不丢焦点）。

## 需求 4：左右屏篇幅差异与滚动对齐

**用户决定：不改渲染，只改滚动联动。** 原因：Markdown 规范下块之间空行不产生任何块级元素，
右屏天然更短（实测篇幅比 0.30~0.81），这是既定事实；为「看起来一样长」去伪造空行间距
会让渲染/导出与其它 Markdown 工具不一致。

**定位到四个缺陷**
1. **长行软换行**：`textarea` 是 `white-space: pre-wrap`，视觉行数 ≠ 逻辑行数（按 `\n` 计数）。
   原「`scrollTop / 可滚动高 × (总行数-1)`」线性估算在长行文档上实测偏 **10 个块**。
   → 新增 `measureSourceLineAxis`（mirror div + 行首零宽 `U+200B` 撑出行盒；
   ⚠️ 空行的 `Range` 矩形全为 0，不能用）实测每块真实 Y，补全成密集轴后二分插值。
2. **无末尾锚点**：最后一个块之后的源码尾部（正是用户加的那堆空行）无法映射
   → 实测右屏到底时左屏只到 **78.7%**。→ 增 `totalSourceLines` 追加末尾锚点。
3. **末尾锚点用错了行**：滚到底时最后一行只在视口**下半部**，视口顶其实是更靠前的行
   （实测文档① `maxScroll=6489` → 视口顶在第 **223.79** 行 / 全篇 266 行）。
   旧实现按「最后一行 ↔ 右屏 max」→ 左屏到底只映射到右屏 **98.6%**（差 26px）。
   → 新增 `lineAtMaxScroll`/`maxScrollLine`，并剔除 `line > maxScrollLine` 的锚点
   （否则端点表乱序、顺序查找提前 break —— 这正是 98.6% 的直接原因）。
4. **含 mermaid 文档贴标数为 0**（两个叠加因）：
   a) 数量自校验数 `body.children`，而 mermaid/katex 会注入 `<script>` 与 `div.mermaidTooltip`
      → 数量永远不等 → **整份文档放弃贴标**；→ 新增 `isAnchorablePreviewChild` 过滤
      （贴标必须用过滤后的**同一个数组**，下标与 `lines[i]` 对齐）。
   b) **`doc.close()` 返回时 `doc.body` 可能仍是 `null`**（`<head>` 里非 async 的 mermaid 脚本
      让解析器停住），旧代码直接 `doc.body.children` 抛 TypeError 被 `catch` 静默吞掉；
      → 改为「body 就绪再贴」（同步 / `load` / rAF / 120ms 定时器四重触发，贴标幂等）。

**实机端到端（三份文档：① 分割线+大量空行 ② 长行软换行 ③ 表格+mermaid）**

## 需求：文档拉到底时反复开合预览，文档会持续往上滚、阅读焦点不断变化

**用户原话**：「文档拉到底，我在编辑模式不断重复关闭预览和打开预览的操作，即不断双击 shift 键，
结果发现文档进度每一次会细微的往上滚动，这样文档不断在滚动就造成了阅读焦点不断的变。」

**实测复现**（逐帧采样 + `scrollTop` setter hook 抓调用栈）：文档在底部时开合一次预览，
`scrollTop` 从 **7582 → 7553.333**，**每轮净丢 28.67px**；且这个值是带循环小数的，
说明必然有 JS 计算写回，而不是浏览器原生行为。

**根因（两层，缺一不成立）**

① **CSS 根因** —— `.source-editor` 的 `padding-inline` 里含百分比：

```css
padding-inline: max(60px, calc((100% - 960px) / 2 + 60px));
```

宽度一变它就**瞬时重算**（实测 `padding-left` 582px → 30px，中间没有过渡）→ 正文列宽突变
→ 软换行行数突变 → `scrollHeight` 从 8833 掉到 5954 → 浏览器把 `scrollTop` 钳到临时 max。

② **组件层直接来源** —— 右屏→左屏的块锚点映射是**有损的**（底部映射回来正好少 28.67px）。
开合过程中 iframe 重新渲染派发 scroll 事件，把右屏位置反算成源码行再写回左屏，每次都少一截。
宽度过渡结束后内容高度恢复 8833，但滚动位置已经回不去。

每开合一轮重复一次 ①②，于是表现为「持续上漂、阅读焦点乱跳」。

**修复**

| 层 | 改动 |
|---|---|
| CSS（治根因） | 给 `padding-inline` 加上与两栏宽度**同曲线同时长**的过渡（0.42s `cubic-bezier(0.33,0,0.67,1)`），正文列宽连续变化，`scrollHeight` 全程平滑，不再触发钳位 |
| 组件（兜底） | 开合期间启用冻结窗口：窗口内左右联动同步、ResizeObserver 锚点补偿都不改写左屏；窗口结束时精确还原（原本贴底就对最新 `max`，普通位置写回原像素） |
| 时序 | 窗口关闭由**布局稳定**驱动（`ResizeObserver` 盯 `scrollHeight`，一变就续期，连续 320ms 无变化才关），而不是写死时长 |
| 最终裁决 | 关窗后再校验 3 次，位置若被开合流程写走就拉回 |
| 补偿 | 关窗后补一次左→右对齐，保证重开的右屏跟随（否则右屏会停在顶部） |

窗口内**用户主动滚动优先**：一旦检测到位置被外部改动（与上次程序写入值偏差 > 1.5px），
立即放弃还原，绝不和用户抢滚动条。

**实机验证（安装版，非构建目录）**

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 开合一次后 gap（距底差） | 1px → **29.67px** | 1px → **1px** |
| 开合两态 scrollTop | 7582 / 7553.333 | 7582 / **7582** |
| 净漂移 | 28.667px | **0.000px** |
| 20 轮反复双击 Shift | 累积上漂 | **0.00px，6/6 PASS** |
| 右屏跟随 | — | 保持底部 100% |

**排查工具改进**：验证探针发现 exe 内联的 dist 仍是旧的（只跑 `npx vite build` 不会更新 exe），
导致多轮误判「修复无效」。现在探针会读 `dist/index.html` 的 hash 并在 exe 字节流里比对，
不一致直接中止并提示 `npx tauri build --no-bundle`；同时修正了 WebView2 后台窗口
`requestAnimationFrame` 被节流（只跑 44 帧就停）导致的采样不全问题。

# 附：第七批问题修复（2026-10-25，同一版本号重新打包）

> 本批 2 条（均在编辑模式分屏场景），在**打包安装产物 + WebView2 CDP 几何测量**下实测通过。
> 质量验证：`tsc --noEmit` exit 0；全量 **318 文件 / 5582 用例**全绿；

## 问题 1：关闭预览后左屏阅读焦点向下偏移（3.1 变 3.3），重开又恢复

**症状**：编辑模式分屏时左屏中央是 3.1 小节；关闭预览（左栏变全宽）后中央变成 3.3 或更后面，
重新打开预览又回到 3.1。阅读体验前后不一致。

**根因**：上一批为消除"反复开合累积上漂"冻结了左栏并**按原像素 `scrollTop` 还原**。
但分屏与全宽下正文列宽不同，长段落软换行数不同——同一像素在更宽布局下指向更后面的内容。
真机逐帧实测：关闭预览后中央小节偏移 **1152px（3.1 章）/ 3744px（7.3 章）**。

**修复**：
1. 非底部开合时不再记录像素，而是记录**视口中央内容锚点**（`captureTextAnchor(textarea, clientHeight/2)`）；
   宽度过渡每帧以及关窗后的裁决校验都用 `restoreTextAnchor` 把"中央那一行文字"拉回中央；
2. 贴底场景仍走上一个批次的 `atBottom`（对齐最新 `max`），保证底部零漂移不回退；
3. 用户主动滚动/输入的判据从"scrollTop 与上次写入差值"改为**真实输入事件**
   （wheel / pointerdown / touchstart / 滚动与输入键；**排除 Shift/Ctrl 等修饰键**，
   否则双击 Shift 的第二次按键会取消还原）；
4. 冻结窗口只在"编辑模式内**单纯**开合预览"时启动（`modeChanged` 闸门），
   不再干扰阅读↔编辑切换的进度恢复。

**重开预览右屏不跟随（同批修复）**：旧实现在解冻后用百分比粗对齐右屏，真机偏差
**6px（3.1 章）/ 37px（7.3 章）**，章节越深偏差越大，用户必须再滚一下左屏右屏才跳回。
现改为解冻后调用 `syncToPreview(force)` 走同一套 `data-src-line` **块锚点映射**，
并在 0/160/480/1000ms 重试（覆盖 iframe 异步渲染）。

**实机验证**

|---|---|---|
| 关闭预览后中央小节偏移 | 1152px / 3744px | **0.084px / 0.272px** |
| 重开预览后右屏偏差 | 6px / 37px | **0px / 0px** |
| 底部 20 轮反复开合 | 0.00px（上一批已修） | **0.00px，6/6 PASS** |

## 问题 2：阅读模式与分屏模式的阅读进度联动丢失

**根因**：阅读→编辑切换时 `previewShown` 会同时由 false 变 true（编辑默认带预览），
上一批的冻结窗口把它误当成"开合预览"启动：在 `applyScroll` 按百分比恢复阅读进度之后，
冻结窗口又把左屏拉回它启动时读到的 textarea 位置（通常是 0/旧值）→ 进度看起来丢失。

**修复**：冻结窗口增加 `viewMode` 闸门——只有 `viewMode` 没变、仅 `previewShown` 翻转
（真正的开合预览）才启动；阅读↔编辑切换完全交给 `pendingScrollRef`/`applyScroll`。
同时解冻后的右屏对齐改为块锚点映射，分屏左右两屏与阅读进度同源。

**实机验证**（把 5.2 / 9.1 小节放到阅读视口中央后切换）

| 步骤 | 实测 |
|---|---|
| 阅读模式 → 编辑/分屏 | 50.00% → **50.00%** |
| 编辑/分屏 → 阅读 | **50.01%** |
| 底部 100% → 编辑 → 阅读 | 100% → 99.98% → **99.99%** |

阅读↔编辑/分屏百分比差 ≤ **0.02pp**，中央小节位置差 ≤ **40px**（探针判定 PASS）。
