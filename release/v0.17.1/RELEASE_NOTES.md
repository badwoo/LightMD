## 二、缺陷修复（用户问题1）

### 含 mermaid / 数学公式的文档进编辑模式崩溃

- **现象**：打开含 mermaid 图 / LaTeX 公式的文档 → 双击 Ctrl 进编辑模式 →
  `TypeError: Cannot set properties of null (setting 'innerHTML')`。
- **根因**（实机逐帧采样定位，`scripts/v0171-lead-i1-cause.mjs`）：iframe 写入流程在
  `doc.close()` 后**立刻**提交 init 状态，造出「init 已更新、`body` 仍为 null」的窗口
  （解析器停在 `<head>` 等 mermaid/katex 脚本，body 最长 ~100ms 后才就绪）；窗口内
  effect 二次运行会走增量分支 → 对 `doc.body.innerHTML` 赋值 → 崩。
- **为什么只有 mermaid/公式的文档崩**：纯文本文档每次都走整篇重写分支（结构上
  进不了增量分支）；破坏性对照已验（纯文本文档 body===null 帧数 = 0）。
- **修法**：init 提交推迟到 body 真正就绪（窗口内二次运行自动回安全的整篇重写）；
  增量分支再加 body 守卫兜底。

## 三、本轮四个用户问题修复

### 3.1 双击 Ctrl 来回切换后阅读进度丢失、跳回文档顶部

- **现象**：以 `明途知识产权-高级数据工程师-沟通场景表.md` 为例，双击 Ctrl 进编辑模式，
  来回几次切换后阅读进度丢失，直接跳到文档顶部。
- **根因**（hook `scrollTop` setter 抓调用栈，`scripts/_lead-i1d-writestack.mjs`，真机文档实测）：
  ```
  t=13284  cm   5 → 8127.3   ← res-source（模式切换恢复，正确）
  t=13317  cm 8127 → 8103.9  ← CM6 measure（-23px，正常）
  t=13754  cm 8104 → 3.9     ← ★ 罪魁祸首
  t=14290  cm    4 → 5       ← 再被写成 5
  ```
  那个调用栈是 `PreviewPane` 的 `syncToSource`（绑在预览 iframe 的 `contentDocument`
  捕获阶段）。机制：
  1. 恢复左屏 → 左屏滚动 → `syncToPreview` 写右屏；
  2. 右屏（iframe 内部文档）的 scroll 事件**经跨文档队列晚约 459ms 才到**；
  3. 到达时方向锁 `SPLIT_SCROLL_LOCK_MS = 250ms` 早已过期 → 被判定成"用户滚了右屏"；
  4. 而此刻右屏还在"刚建出来、逐帧追赶"的阶段（`previewTop` 16/32/48/64/78）→
     反算出**源码第 0 行** → 把左屏写成 4px。
  
  一旦左屏被写成 0，下一轮切换的基准就是顶部 → **永久丢失**（实测 6/6 轮全部 `top=0`，
  `localStorage` 进度被冲成 `0.0002`）。
- **修法**（`PreviewPane.tsx`）：不加大时间窗（那会把"用户真的去滚右屏"也判成回声，
  造成双向联动死区），而是**按值识别自己的写入**：在唯一的右屏写入点记录
  `lastProgrammaticPreviewTop`；`syncToSource` 读到右屏值与该记录相等（±2px 取整容差）
  → 确定是回声，直接返回。
  失败方向的不对称性正是选它的理由：误判 = 少同步一次（可自愈）；
  漏判 = 阅读进度被清成 0（不可自愈）。
- **验证**（真实构建产物 + 用户文档）：

  | 判据 | 修前 | 修后 |
  |---|---|---|
  | 切回阅读 `scrollTop` | 0 ×6 | 8152 ×6 |
  | 阅读进度 pct | 0 ×6 | 0.4998 ×6（基线 0.5） |
  | `localStorage` 进度 | 被冲成 0.0002 | 0.50003 恒定 |
  | 视口中央内容 | 漂到文档开头 | 与基线一致 |
  | 把左屏从 >1000 写回 <100 的次数 | 1 | **0** |

  慢速 6 轮 + **快速连切 8 轮**全部通过。

### 3.2 无格式文本的格式刷应生效（用来把有格式刷成无格式）

- **现象**：对没有格式的文本点格式刷，提示「所选内容没有可复制的格式（请选中带格式的
  文字，如加粗、标题、列表）」并拒绝。
- **口子**：`isSnapshotEmpty()` 把「无格式纯文本」判成"空快照"。但这等于让用户
  **无法用格式刷做「去格式」** —— 而"无格式"本身是合法的格式值。
- **修法**（`formatPainter.ts` + `FormatMenuHost.tsx`）：
  - 新增 `isSnapshotMissing()`：只有真的没采到快照（`null`）才拒绝；
  - 新增 `isSnapshotPlain()`：识别"无格式"，供 UI 给出准确提示；
  - 旧 `isSnapshotEmpty()` 标记 `@deprecated` 保留（存档测试仍用），生产路径不再用；
  - 源码侧顺手修掉一个隐性缺陷：原 `if (snapshot.marks.length > 0)` 会让**空 marks
    跳过剥离**，改为 `marks.length > 0 || blockType !== null`，让"刷成无格式"真正执行剥离。
- **验证**：`**已加粗目标**` → 刷无格式源 → **`已加粗目标`**（格式被清除）。

### 3.3 格式刷支持对选中文本应用（而不是整个段落）

- **现象**：格式刷只能整段/整行应用，"只想把这几个字加粗"做不到。
- **根因（两层）**：
  1. 应用入口把范围写死成整段（`$pos.start(depth)…$pos.end(depth)` / `getLineRange`）；
  2. 即便记了选区也没用 —— 应用挂在 `click` 上，而**编辑器的 `mousedown` 先跑并把
     选区塌缩到点击点**，等 `click` 时只能读到光标。
- **修法**：
  - 新增 `resolvePainterApplyScope()`：**有选区 → 只刷行内**（`inlineOnly`）；
    无选区 → 沿用整段语义（旧行为一字未变）；
  - 新增 `buildPmInlineOnlyTr()`（PM 选区级，**不碰块级** —— Markdown 里不存在"半个标题"）；
  - 新增 `applyMarksToSourceRange()`（源码选区级，**保留行首前缀**）；
  - 在 `mousedown` 的**捕获阶段**记录选区（早于编辑器自己的处理器）；
  - 用 `armSelectionRef` 记下 arm 时的源选区并**排除残留**（否则会把格式重新刷回源自己
    —— 这是探针中抓到的真实缺陷）；
  - 加重入保护，避免同一次手势内二次应用产生畸形嵌套。
- **验证**：

  | 用例 | 结果 |
  |---|---|
  | 源码面选中 `DELTA` 刷粗体 | `第四段纯文本 **DELTA** 供选区级测试使用。`（整行其余不动）|
  | `## 标题前缀 正文部分 GAMMA。` 选中「正文部分」 | `## 标题前缀 **正文部分** GAMMA。`（前缀保留）|
  | 阅读面（PM）选中 `DELTA` | `<strong>` 只含 `DELTA`，整段**不泄漏** |
  | 仅光标（无选区） | 仍刷整行 —— 旧语义无回归 |

### 3.4 双击 Shift 开/关预览后两屏不对齐

- **现象**（用户原话）：
  > 「双击 shift 开关，右屏会比左屏超前好几段内容，**但通过鼠标滚动文档，
  >  左右屏文档又慢慢对齐了**」
- **根因**（trace 取证，`scripts/_lead-p4k-inputs.mjs` + `_tmp-q1.mjs`）：
  开合预览后的"主动重新对齐"走 `syncPreviewAfterToggle()` / `realignLayoutNow()`，
  它们最终调用 `syncToPreview(force=true)`——`force` 只跳过了**方向锁**，
  但**没跳过"每帧最多走 16px"的逐帧钳制**（`clampPreviewTarget`）。实测：
  ```
  next    = 21826   ← 映射算出的正确目标
  clamped = 23918 → 23902 → ... → 23424 → 23408 → 23392 → 23376
            ↑ 每帧只前进 16px（因为左屏已跳完，dLeft=0 → allowed=ALLOW_ABS=16）
  ```
  要跨 2090px 需 131 帧 ≈ **2.2 秒**，而 realign 链末点是 1600ms、窗口上限 2500ms
  ⇒ **追不上就永久停在错的位置**（实测停 23376，差 1550px ≈ 2 屏）。
- **"滚一下就对齐"的解释**：用户滚动时 `dLeft` 变大 → `allowed = dLeft × 3` 变大
  → 单帧走得更多 → 若干帧后追上。**不是自愈，只是把 allowed 变大了。**
- **修法**（`scrollSyncPolicy.ts` + `PreviewPane.tsx`）：
  `clampPreviewTarget` 新增 `force` 参数。**开合预览后的程序主动对齐**传 true，
  跳过逐帧钳制直接写目标值（仍保留"非有限值不写垃圾"护栏）；
  **用户滚动路径不传**，逐帧平滑跟随语义一字未变。
  这与既有设计一致：`syncToPreview(force)` 早就用 `force` 跳过方向锁，
  本次只是把"跳过物理钳制"这层语义补齐。
- **验证**（同一探针、同一份用户文档，A/B 对照）：

  | 判据 | 基线（修复前） | 修复后 |
  |---|---|---|
  | 左屏中央那段内容离右屏中央的距离 | **-1242.6px** | **-27.6px** |
  | 判定 | FAIL | **PASS** |
  | 右屏 scrollTop 收敛值 | 23376（目标 21826，差 1550px） | **21826（精确命中）** |
  | realign 链结束时位置 | 每帧 16px 爬不完 | 480ms 即到位 |

- **配套护栏**（`utils/previewGeometry.ts`，纯函数 + 13 条契约测试）：
  关闭预览时预览壳宽度过渡到 0，iframe 内部每字单独折行 → `scrollHeight`
  从 6130 暴涨到 **175405**（29 倍）。原有闸门只查"贴标>0 且可滚动"，
  这种情况下**照样放行** → 用畸形几何算位置。新增几何健全性判据
  （宽度 > 80px 且高宽比 ≤ 500），不满足则跳过本次写入。

## 四、CM6 能力适配第一批（P0 六项）

### 4.1 智能回车（A1）——本版用户价值最高的一项

源码面按 Enter 不再只是普通换行：

| 场景 | 旧行为 | 新行为 |
|---|---|---|
| 列表 / 任务项 / 引用行尾 Enter | 光标顶格，手动补 `- ` | 自动续出标记（`- ` / `- [ ] ` / `> `） |
| 有序列表 `3. xxx` Enter | 不续编号 | 自动 `4. ` 递增 |
| 空列表项 Enter | 残留空项 | 自动退出列表 |
| 行首 Backspace | 与上一行粘连、破坏结构 | 一次删净列表/引用标记（取消条目） |

- 任务项续行自动重置复选框（`- [x]` → 新项 `- [ ]`）。
- **撤销口径不变**：命令不装 CM6 `history()`，事务经统一时间线上报（typing），
  一次回车 = 一步撤销，跨模式撤销不回退。
- 键位优先级不回退：Slash 命令确认（Enter）走捕获监听、优先于智能回车；
  IME 组合中的 Enter 交输入法。
- 已知边界（CM6 官方语义）：两项紧凑列表的**第二个空项**按 Enter 是"插空行变
  松散列表"而非退出；三项及以上列表的空末项正常退出。行为已由测试锁定。

### 4.2 代码块内嵌语言高亮（A2）

围栏代码块（```` ```js ```` / ```` ```python ```` 等）按语言逐 token 上色
（此前整块只有一个颜色）。语言来自 `@codemirror/language-data` 注册表，
**按需懒加载**：未打开过的语言不进主包，加载完成自动重解析，不增加启动负担。

### 4.3 选中词即高亮 + Ctrl+D（C1 / C2）

- **选中词即高亮**：双击选中一个词，全文相同文本自动亮起（点别处即消失）。
  与搜索面板互补：面板管"主动检索/替换"，这个管"边读边看"。
- **Ctrl+D**：选中下一处相同文本，逐次累加多光标 → 多处同时改写
  （批量改名场景）。已过滤 defaultKeymap 中 emacs 习惯的 Ctrl-d（删字符），
  避免 Windows 上抢键。

### 4.4 空文档占位 / 拖拽落点 / 文末留白（E4 / E5 / E6）

- **占位提示**：空白文档显示「开始输入 Markdown…（/ 唤起命令）」，打字即消失。
- **拖拽落点光标**：拖动文本/文件时插入位置显示竖线，落点可视。
- **文末留白**：每行都可滚动到视口顶部 —— 打字机模式**末行居中**自此成立
  （此前文档最后一行永远贴底、居中失效）。滚动进度 100% 仍对应文档末行。

## 六、已知限制

- 多光标仍是"能建能打字，但格式化/替换/AI 只认主选区"的半开状态（v0.17.0 遗留，
  见 CM6 适配清单 I1），Ctrl+D 的多处同改覆盖"打字覆盖全部选区"场景；
  多点格式化待后续版本。
- 行内配对（Tab 跳出配对 / Backspace 成对删除）在 CM6 路径仍是 v0.17.0 已知
  缺口（TODO v0.18），本版未动。
- 两项紧凑列表的空第二项按 Enter 变松散列表而非退出（CM6 官方语义）。
- 空文档占位文案跟随**挂载时**界面语言，运行中切换语言不即时刷新（极低频组合）。
- **格式刷选区级只作用于行内格式**：加粗/斜体/删除线/行内代码/下划线/高亮都支持选区级；
  但标题/列表/引用是**块级**概念（Markdown 里不存在"半个标题"），选区级一律不改块级 —
  需要改块级时请不选任何文字、直接点目标段落再落笔。
- **格式刷的"回声防护"按值识别**：极端情况下（用户手动把右屏滚到与我们上次写入
  **完全相同的像素**）那次反向同步会被跳过一次，再滚一下即恢复。
  选择这个取舍是为了让失败方向落在"少同步一次"，而不是"阅读进度被清成 0"。
- `SPLIT_SCROLL_LOCK_MS = 250ms` 的方向锁本轮**未改动**（它同时服务其它路径），
  本轮叠加的是"按值识别回声"这道更精确的防线；若后续要把方向锁也收紧，另开范围。
