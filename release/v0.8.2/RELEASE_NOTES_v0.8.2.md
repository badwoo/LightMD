## 二、版本内容

本版合计交付 **3 项动画优化 + 2 项排序调整 + 9 项问题修复**（基线 0.8.1）。

### 2.0 反馈修复（第二轮）

| # | 问题 | 根因与修复 |
| --- | --- | --- |
| R1 | **点击子文件夹软件卡死** | 树节点动画容器在**渲染期调用 `setState`**：展开"内部还有子文件夹"的目录时触发「渲染 → setState → 再渲染」无限循环，React 抛 `Too many re-renders` 后整棵侧栏被卸载。现状态更新全部移入 `useEffect` |
| R2 | **侧栏偶尔拖不动** | 与 R1 同源——侧栏被崩溃卸载后自然既点不动也拖不动。R1 修复后随之解决；拖拽兜底（按键已松开 / 窗口失焦立即清理监听与 `section-dragging`）保持有效 |
| R3 | **打开文件夹后打开 md，图片不渲染**（直接打开正常） | Rust `resolve_path` 的 `canonicalize()` 返回 Windows 扩展长度路径 `\\?\D:\...`，`list_dir` 转成正斜杠后变成 `//?/D:/...`。相对路径图片解析把 `?` 当作普通路径段，转 asset URL 时被百分号编码为 `%3F%2F`（`.../%3F%2FD%3A%2F...`），资源协议随即找不到文件。菜单直接打开传入的是未被 canonicalize 的原始路径，所以正常。现 Rust 侧统一剥离该前缀，前端 `stripExtendedPathPrefix` 再兜一层 |
| R4 | **标题栏「新建 > 新建文件夹」没反应** | 旧实现走原生 `prompt()` + `save` 保存对话框，既不是应用内弹框、也无法选择目标路径。现改为派发命令由侧栏打开应用内**新建文件夹弹窗**（居中显示，输入名称 + 勾选已打开文件夹或自定义路径） |
| R5 | **点击栏内已打开文件会重新置顶** | 「打开的文件」栏此前按"最近使用"排序，点击切换也会置顶。现改为**仅"新打开"时置顶**，点击切换只更新选中态、不改变顺序 |

### 2.1 动画优化

#### A1 · 打开：从左到右平滑进入

- **文件夹栏**（侧栏中每个已打开的文件夹）：打开时从左侧滑入，同时高度 0 → 内容高展开
- **「打开的文件」条目**：打开文件时条目从左侧滑入
- **文件夹树节点**：展开某目录时，其子节点从左侧滑入并展开高度
- 三者共同表现：**新内容平滑进入，下方已有内容被平滑地推下去**

#### A2 · 关闭：严格串行三拍（本版核心修复）

关闭动画拆成三个依次进行的阶段，彻底消除"两个动画同时发生"的观感：

| 阶段 | 动作 | 时长 |
| --- | --- | --- |
| ① | 向左水平滑出 + 淡出（占位高度保持不变） | 360 ms（条目 600 ms） |
| ② | **停顿一拍**，让两个阶段在视觉上分离 | 120 ms |
| ③ | 高度平滑收起到 0 → 下方内容上移补位 | 480 ms（条目 400 ms） |

**修复的根因**：此前关闭文件夹栏的快照在 **360 ms** 就被卸载，而整条串行动画需要 **960 ms**——
快照提前消失导致下方栏在高度收起前瞬间跳到新位置，看起来就像"左滑消失"和"上移补位"同时发生。
现在快照保留到整条动画播完（`SECTION_OUT_TOTAL_MS` / `ITEM_OUT_TOTAL_MS`）才移除。

#### A3 · 关闭中间那一项：原位消失

- 关闭位于**中间**的文件夹栏或「打开的文件」条目时，滑出块**留在它原来的位置**上滑出，
  下方内容上移补位
- 此前所有滑出块统一追加到列表末尾，视觉上像"底部凭空滑出一条"
- 实现：以"关闭前那一帧的完整顺序"为坐标源，计算滑出块应插入的槽位
  （槽位 k = 渲染 k 个存活条目之后），条目与文件夹栏共用同一套坐标逻辑

#### A4 · 文件夹树节点新增收展动画

- 展开目录：子节点左滑入 + 高度展开；收起：先左滑出、再收起高度
- 动画容器按**文件夹路径固定 key**，父节点因加载子目录 / 刷新重渲染时不会打断动画
- 收起动画播完才卸载子节点（期间保留子节点快照）

### 2.2 排序调整

#### S1 · 最新打开的文件夹栏置顶

- 新打开的文件夹栏插入到**第一位**（其余栏依次下移）
- 同时最多 5 个文件夹，超出上限时挤掉**最久未打开**的那个

#### S2 · 「打开的文件」条目仅"新打开"时置顶

- 新打开的文件排到第一位，其余条目保持相对顺序
- **点击栏内已打开的文件切换时不再重新置顶**（只更新选中色）——用户反馈调整
- 排序采用"最近打开顺序表"实现且保证幂等（同一帧内重复计算不会让顺序抖动）
- 栏内选取态与快捷键（`Delete` / `Ctrl+1` / `Ctrl+2`）仍以原索引为准，不受排序影响

### 2.3 问题修复

| # | 问题 | 修复 |
| --- | --- | --- |
| F1 | 重新打开文件夹时，已折叠目录的子目录缓存被清空 → 收起动画无内容可渲染（动画跳变） | 刷新时按"磁盘上真实存在的目录"保留折叠目录的有效缓存 |
| F2 | 「打开的文件」栏条目数量 / 选中色与打开的标签不一致 | 栏条目改以「打开的标签」为唯一真相源逐帧对齐；激活态统一按条目 key 判定 |
| F3 | 「打开的文件」栏标题栏结构与新版样式不匹配 | 标题与快照按钮组为左侧组，缩小/放大按钮居右 |
| F4 | 关闭文件夹栏时滑出快照提前卸载 | 由 360ms 改为整条串行动画总时长 960ms |
| F5 | 版本号未同步 | 三处同步升级：`package.json` / `src-tauri/Cargo.toml` / `src-tauri/tauri.conf.json` 均为 `0.8.2` |

## 四、升级建议

- 覆盖安装即可，用户设置与历史版本快照保留
- 无快捷键变更，无需额外适配
- 动画时长均为常量（`SECTION_SLIDE_OUT_MS` / `SECTION_COLLAPSE_DELAY_MS` / `SECTION_COLLAPSE_MS` /
  `ITEM_*` / `TREE_SLIDE_*`），如需更快或更慢可直接调整
