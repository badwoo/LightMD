## 二、版本内容

本版合计交付 **3 项新增功能 + 2 项功能调整 + 2 项问题修复**（基线 0.8.2，需求编号沿用实施计划）。

### 2.1 新增功能

#### N1 · 状态栏实时显示光标行列（需求3）

- 底栏右下角实时显示 `行 N 列 M`；**选中文字时追加 `已选 N 字`**，取消选区后立即消失
- 阅读模式（所见即所得）、源码模式、分屏模式**均生效**
- **行号语义**：每个块（标题 / 段落 / 列表项 / 代码块 / 引用 …）占 1 行，块内硬换行（行尾两空格或反斜杠换行）各占 1 行，表格按表行计，块与块之间的空行不计入；列号为光标在当前块内的字符位置
- **顺带修复一个既有缺陷**：旧实现用 `doc.textBetween(0, pos).split("\n").length` 算行号，而 `textBetween` 未传块分隔符时**不在块之间插入换行**，导致常规 Markdown 文档里行号**恒为 1**。现改为结构化行号计算，顺带不再拼接光标前的全文

#### N2 · 窗口大小记忆（需求4）

- **首次安装 / 首次启动**仍默认**最大化**；此后以什么窗口状态关闭，下次就以什么状态打开
- 缩小窗口（如 900×600）关闭 → 下次同尺寸打开；移动位置后关闭 → 下次同位置打开（**多显示器 / 副屏位置同样保留**）；最大化关闭 → 下次最大化
- 采用 Tauri 官方插件 `tauri-plugin-window-state`（锁定 **2.4.1**），并**显式收窄状态标志**为「大小 / 位置 / 是否最大化」，不记忆全屏等状态，避免"偶然全屏一次，以后每次启动都全屏"

#### N3 · 跨会话记住文档阅读位置（需求6）

- 读到文档中部后关闭软件，重启并自动恢复该文档时**仍在原位置**（按百分比恢复，误差一屏以内）
- 被一同恢复的其它文档、以及**未落盘的临时文档**都各自记住自己的位置
- 低开销设计：位置按标签记录，落盘走「**5 秒心跳 + 关闭前冲刷**」且仅在进度确实变化时写入；**滚动路径仍是内存 `Map.set`，零新增开销**。一次落盘约「打开标签数 × 40 字节」（通常 < 2KB，不在滚动路径上）
- 关闭「启动时载入上次打开的文件」开关后，不恢复文件且清除已记录的阅读位置（无残留）

### 2.2 功能调整

#### C1 · 「最近打开」扩容到 66 条 + 显示打开日期（需求1）

- 此前界面只渲染 **前 10 条**（数据层上限 50）；现完整展示全量列表，条目多时**在该栏内滚动**浏览
- 上限提升为 **66 条**，**最新打开的排在最上面**；超过 66 条后**最早打开的那条被清除**
- 鼠标**悬停在条目上**显示：完整文件路径 + `最近打开：YYYY/MM/DD HH:mm`（本地时区）
- 条目右侧保留相对时间（刚刚 / N 分钟前 / N 小时前 / 月/日）

#### C2 · 启动恢复定位到最后停留的标签（需求5）

- 此前恢复流程写死"激活第一个真实文件"，若关闭前最后停留在**临时文档**，重启后会被强制切到真实文件（用户感知为"载入上次打开的文件对临时文件不生效"）
- 现按**上次会话的活跃标签**定位：临时标签按 id、真实文件按路径；记录缺失或对应标签不存在时回退到原逻辑（保证旧会话数据与首次启动行为不变）

### 2.3 问题修复

#### F1 · 「打开的文件」栏双高亮（需求2）

| 项 | 内容 |
| --- | --- |
| 现象 | 栏内点击条目 A 后从标签栏切到 B，栏内 **两个条目同时高亮**（A 的键盘选中背景与 B 的激活背景，两者背景色原本相同） |
| 根因 | `selectedTempIdx`（键盘操作目标）只在栏内点击时设置，**从不随激活条目变化失效** |
| 修复①（本质） | 键盘选中项随激活条目变化失效；**唯一例外**是"本次激活正由栏内点击产生"——保证"点击 A 后直接按 `Delete`/`Ctrl+2` 仍关闭 A"（键盘语义不回退） |
| 修复②（防复发） | 键盘选中指示从"同色背景"降级为**左侧 2px accent 竖线**，与激活项整行背景明显可区分，任何状态组合下都不会再出现两个高亮块 |

#### F2 · 状态栏"行"号恒为 1

见 N1 末段（旧 `textBetween` 公式缺块分隔符）。本版一并修正。

## 三、滚动性能评测（需求7）

### 3.1 评测结论：不是底层框架的问题

用真实 Chromium（headless，1400×900，交替顺序、冷/热滚动各两轮）对 **1.8 万行 / 9000 个顶层块 / 66 万字符**文档实测：

| 变体 | 冷滚动 avg | 热滚动 avg | LongTask | scrollHeight |
| --- | --- | --- | --- | --- |
| **基线（本版代码）** | **16.67 ms（60 fps）** | **16.67 ms（60 fps）** | **0** | 595087 |
| `content-visibility: auto`（原计划方案） | 70.38 / 66.89 ms（14 fps） | 73.55 / 52.22 ms | 每帧 1 个（~70 ms），合计 13~17 s | 807745（**估值撑大 36%**） |
| `contain: layout style paint` | 16.67 / 17.86 ms | 16.67 ms | 0~2 | 595247 |
| `content-visibility` + 缓存 `scrollHeight` | 77.12 ms | 76.79 ms | 每帧 1 个 | 821489 |

- 基线已是 **60 fps / 零长任务**：Tauri/WebView2 的 Rust 层不在滚动路径上，瓶颈也不在"整篇 DOM"这一层
- 计划中的 `content-visibility: auto` 方案实测**让滚动慢约 4 倍**（文档打开耗时亦无收益：219 ms vs 234 ms），**故不采用**；`contain` 隔离无任何可测收益，同样不引入
- 根因：近万顶层块在滚动中持续做**延迟布局**，且估值尺寸与真实高度偏差（scrollHeight 被撑大 36%）引发大范围重排；变体 4 证明**不是**"滚动处理器读几何"造成的
- 结论、数据与"勿再盲目重加"的说明已写入 `src/styles/editor.css` 注释，并有单元测试锁定

### 3.2 本版实际落地的优化项

| 优化 | 效果 |
| --- | --- |
| 选区变化不再全量序列化文档（`getText` 改惰性） | 18k 行文档单次选区变化 **0.778 ms → 0.072 ms**（约 1/11）：行号计算 0.538 → 0.072 ms，`doc.textContent` 由"每次光标移动/击键"降为"300 ms 防抖内至多一次" |
| 行号改结构化计算 | 零字符串分配、O(光标前的块数)，替代"拼接光标前全文 + `split` 数组" |
| 图片懒加载 | 图片节点输出 `loading="lazy"` + `decoding="async"`，大图解码不再阻塞合成帧 |
| 滚动监听全部声明 `passive` | 浏览器无需等待 JS 即可提交合成帧 |

## 五、升级建议

- 覆盖安装即可，用户设置、收藏、最近打开记录与历史版本快照全部保留
- **无快捷键变更**，无需额外适配
- 行为变化提醒：
  1. 「最近打开」现在展示全部 66 条（此前只显示 10 条）
  2. 窗口尺寸/位置会被记忆：若希望恢复默认，删除 `%APPDATA%\com.lightmd.app` 下的窗口状态文件后重启
  3. 关闭「启动时载入上次打开的文件」后，已记录的阅读位置会一并清除
