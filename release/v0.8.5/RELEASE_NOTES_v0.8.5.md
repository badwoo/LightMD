## 二、版本内容

本版合计交付 **2 项新功能 + 1 项安全调整 + 5 项动效/细节优化**（基线 0.8.4，需求编号沿用用户需求清单）。

### 新增功能

1. **文件删除进回收站（需求 2）**：文件树中对文件或子文件夹执行删除时，统一移入**系统回收站**（Windows 原生 IFileOperation），误删可随时从回收站还原；确认弹窗与提示文案同步改为「移到回收站」语义。
2. **「最近打开」支持文件夹（需求 8）**：最近打开的文件夹与文件**按时间混排**在同一列表（文件夹带专属图标），点击文件夹条目即打开为文件夹栏；列表总量上限 66 条合并计数。

### 安全调整

3. **移除「文件管理」工具栏全局刷新按钮（需求 1）**：实时刷新已覆盖文件增删改同步，刷新入口收敛为**右键菜单「刷新」**与 **Ctrl+R**（文件树搜索按钮旁的刷新按钮不再显示）。

### 界面与动效优化

4. **md 文件图标优化（需求 3）**：文档条目图标由红色铅笔 emoji 换为自绘 SVG——同款纸+笔构图，笔改为**淡蓝灰**配色，纸张颜色随深浅主题自适应。
5. **文件树搜索框动画（需求 4）**：点击搜索按钮，搜索面板顺滑下拉展开（220ms）/ 收回（180ms），收回期间不响应误点击。
6. **排序下拉动画（需求 5）**：排序菜单从按钮方向顺滑下拉（200ms）/ 收回（160ms），三条关闭路径（点外部/点菜单项/再点按钮）均走收回动画。
7. **新建弹窗过渡动画（需求 6）**：新建文件夹、新建文件弹窗打开时 overlay 淡入 + 弹窗轻微上浮缩放出现（180ms）。
8. **底部搜索面板「神灯精灵」动画（需求 7）**：底部栏搜索按钮呼出的搜索面板从按钮方向沿弧线轨迹缩放淡入，带双层模糊**残影尾巴**跟随（呼出 260ms / 收回 220ms），收回时沿原轨迹缩回"灯中"，还原阿拉丁神灯精灵的出现与回归效果。

> 所有动效均使用合成层属性（transform/opacity/filter），不引发布局抖动；系统开启「减弱动态效果」时自动降级为直接显示/隐藏。

## 四、同版本迭代修复与优化（2026-09-26）

首轮发布后的用户验收反馈修复（同版本内迭代，不改版本号）。

1. **md 文件图标恢复**：文档条目图标恢复为原来的 📝（撤销上版替换的自绘铅笔）。
2. **「打开的文件」条目图标改为打开的小书本**：形状类似 📖，真实文件保持蓝色、未保存的临时文件保持黄色（说明：emoji 无法指定颜色，故以自绘 SVG 实现，配色与原图标完全一致）。
3. **搜索面板动画方向调整**：文件树搜索面板改为**从左往右**顺滑展开、**从右往左**顺滑收回（220ms/180ms）。
4. **新建弹窗背景闪动修复**：根因是遮罩淡入与弹窗动画的透明度双层叠加（动画前半程遮罩过透，背景大量透出）+ 缺合成层提升提示导致整屏逐帧重混合。已将遮罩淡入移至独立伪元素层、为弹窗与遮罩强制合成层提升，动画顺滑无闪动。
5. **神灯精灵效果重做**：新增从底部栏搜索按钮到搜索面板的**垂直丝带光带**——打开时丝带先从按钮生长、面板沿丝带滑到屏幕中间后丝带顺滑消散；关闭时丝带重新亮起连接按钮、面板沿丝带滑回、丝带收回按钮，"从灯中现身/被吸回灯中"的观感具象化。
6. **「最近打开」改为纯历史记录**：关闭文件或文件夹**不再移除**最近打开中的对应条目；条目只在文件/文件夹被移动或删除（含外部操作）时显示 ⚠ 提示，永不自动删除。应用启动时恢复的文件夹改用独立的会话快照，与最近打开历史彻底解耦（旧版本数据自动兼容）。

> 本轮回归：全量 165 个测试文件 / 2945+ 用例通过，`tsc --noEmit` 零错误。

## 五、同版本迭代修复与优化（第二轮，2026-09-26）

第二轮用户验收反馈修复（仍为同版本内迭代，不改版本号）。

1. **新建弹窗「打开动画期间背景杂乱闪动」彻底修复（反馈 1）**
   - **根因（用 headless Edge 逐帧定格复核确认，非推测）**：弹窗本体动画里带了
     `opacity: 0 → 1`。弹窗是一个 420px 宽的不透明方块，淡入前半程背后编辑器/文件树的
     文字是**透过弹窗**显形的；而弹窗同时还在做 `scale`，透出来的背景逐帧位移，
     观感就是"背景在弹窗里杂乱闪动"。此外遮罩也从全透明起步且比弹窗慢，动画第一帧
     整屏还全亮、随后才压暗，形成一次全屏明暗跳变。（上一轮"双层 opacity 相乘"的推断
     只解释了一半，真正让背景被看见的是"弹窗自己在淡入"这件事本身。）
   - **修法**：弹窗本体**完全不做 opacity 动画**——第一帧起就是不透明实体，背景永远不可能
     透出来；观感由 `transform`（上浮 12px + 轻微缩放 0.96→1，180ms）承担，它是合成层属性、
     在合成器线程完成，主线程即使短暂繁忙也不会掉帧。遮罩淡入继续挂在 overlay 的
     `::before` 独立层（只动一个纯色层的透明度，代价极低）。
   - **配套**：两个弹窗的表单重置由 `useEffect` 改为 `useLayoutEffect`（在浏览器绘制前落定，
     打开动画途中不再改一次勾选/输入态）；FileTree 传给弹窗的目标文件夹列表加 `useMemo`
     （旧写法在 JSX 里 `.map()`，每次重渲染都产生新数组引用，会让弹窗表单重置多跑一遍）。

2. **底部搜索面板「神灯 / 橡皮尾」重做（反馈 2）**
   - 去掉上一版"蓝色激光丝带 + 双层残影"的实现，改为**与窗口同色同边**的"被拉长的本体"：
     尾巴填充 `var(--bg-primary)`、描边 `var(--border-color)`，与搜索面板完全一致，
     从底栏搜索按钮长出来，不再是发光光带。
   - **打开**：面板纵向压扁着从按钮处被"拉"出来（X 不缩放），尾巴与面板共用同一段位移
     关键帧，顶端始终贴着面板下沿；面板在屏幕中间落定后，尾巴自面板一端被顺滑吸回本体消失。
   - **关闭**：尾巴先从面板下沿垂落、连到底栏搜索按钮，随后面板与尾巴一起被吸回底栏
     （面板压扁着坠回，像被底栏吸走）。
   - **尾巴随窗口位置实时变化**：长度、宽度、朝向、裁剪窗全部由开合瞬间实测的
     "按钮 ↔ 面板"几何算出——窗口拖到左边，尾巴就从左下斜着连回按钮；拖得越远，尾巴越细长。
   - 尾巴只做 `transform/opacity`，且只在开合那 0.5s 内存在；拖拽窗口期间没有任何额外开销
     （不监听、不逐帧计算）。系统开启「减少动态效果」时尾巴不渲染、面板直接显隐。
