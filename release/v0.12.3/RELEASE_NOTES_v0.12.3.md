# LightMD v0.12.3 发布说明

> 发布日期：2026-10-12 ｜ 基线：v0.12.2 ｜ 定位：**三模式一致性修复**（回车语义回归正解）
>
> 本版针对用户实机反馈的四个问题：**① 阅读模式编辑后切到编辑/分屏模式凭空多出空行；② 阅读模式编辑文字行间距过高、与其他文档不一致**（以上两条第二轮一并修复）；**③ 刚按完回车就切模式时源码里出现 `<br>` 字样；④ 编辑区与分屏右侧不跟随设置里的「行高」**。
>
> v0.12.2 曾把「回车 = 段内换行」整体回退，本版**以更完整的方式重新落地**：把回退时丢掉的「续行行首转义」与「段内换行边界用 `<br>`」一起补回，并改用 headless Chrome 实测行距取证，不再只凭源码 diff 判断。

## 二、版本内容

### 2.1 【三模式一致】阅读模式回车 = 换行（N 次回车 = N 个换行）

**现象**：阅读模式里编辑文本，**只按了一次回车**，切到编辑 / 分屏模式却发现两行之间**多出一个空行**；连按两次回车则多出两个空行。

**根因**：阅读模式的回车走 `baseKeymap` 的 `splitBlock`（= 新建段落），而 Markdown 的**段落之间必须有一个空行**。于是"一次回车"在源码里被写成 `第一行\n\n第二行` —— 用户按了 1 次回车，源码却出现 2 个换行（一个空行）。

**修复**：顶层普通段落内，`Enter` 改为**段内换行**（`hard_break`）：

| 阅读模式操作 | 源码形态 | 说明 |
|---|---|---|
| `Enter` × 1 | `第一行  ␊第二行` | 相邻两行，**无空行** |
| `Enter` × 2 | `第一行␊␊第二行` | 中间**一个空行** |
| `Enter` × N | N 个换行 | 与阅读模式看到的行结构一一对应 |

**作用域严格限定「顶层普通段落」**：列表 / 任务项内回车**仍继续分裂条目**，引用 / 标题 / 表格 / 代码块内语义完全不变（代码块内回车仍是原生换行）。段首回车、或连按两次回车，同样得到新段落。

**`Shift+Enter` 与 `Enter` 对调**：顶层普通段落内 `Shift+Enter` = **新建段落**（源码空行）—— 想直接"另起一段"时始终有一个**一次按键**的入口；列表 / 引用 / 标题内仍是原有的段内硬换行。

> **老文档不受影响**：此前用回车分段的内容，源码本来就是空行，本版不会改写；只有**此后新输入的回车**才按新语义写成一个换行。若你希望某处保持"段落"，按 `Shift+回车` 或连按两次回车。

### 2.2 【观感修复】阅读模式行距回归默认（三模式逐像素一致）

**现象**：阅读模式里编辑文字**行间距很高**，与打开的其他文档观感不一致。

**根因**：与 §2.1 同源。新建段落会叠加 `.ProseMirror > p` 的 `0.8em` 上下 margin（`--editor-paragraph-spacing` 的兜底值）；headless Chrome 实测：**段落行距 41px**，而正常行高只有 **28.8px**（16px 字号 × line-height 1.8）—— 比段内换行明显更松，且用户在阅读模式里感知不到"这是一次段落分隔"，一切换到源码模式就看到空行。

**修复**：段内换行只吃 `line-height`，实测行距 **29px ≈ 编辑模式 textarea 的 28.8px**，阅读 / 编辑 / 分屏三模式行距一致。

| 场景 | 修复前行距 | 修复后行距 | 编辑模式对照 |
|---|---|---|---|
| 回车产生的相邻两行 | 41px（段落 margin 叠加） | **29px** | 28.8px ✅ |
| 连按两次回车（空行） | — | 段落间距 0.8em（可在设置「段间距」调） | 一个空行 |

> 段落间距（连按两次回车、或源码里本来就有空行的段落）仍由 **设置 → 排版 → 段间距** 控制，不需要"高行距"时把它调小即可；本版**未改动**任何默认排版值，避免影响既有文档观感。

### 2.3 【数据安全】段内换行的往返保真（补齐边界 + 恢复续行转义）

回车 = 换行后，"段内换行"成为高频形态，以下边界**用「行尾两空格」无法表达**（实测往返会丢换行或把块拆开），本版改用显式 `<br>`（解析端白名单会还原为同一节点）：

| 边界 | 用 `"  ␊"` 的问题 | 现方案 |
|---|---|---|
| **段首**的换行 | 行首两空格被当作空行（实测 `"  ␊A"` 直接拆成两个段落） | `<br>`，往返稳定 |
| **相邻硬换行** | 中间行只剩空白 → 被判为段落边界，重开后一个段落被拆成两块 | `<br><br>` |
| **表格单元格内**换行 | 真实换行会截断 GFM 表格行（v0.8.0 P0-1 同源） | `<br>`（沿用） |
| **列表项 / 引用内**的段末换行 | 这两条序列化路径把段落内容**嵌进带前缀的行**（`- ` / `> `），内嵌换行会把块拆开（实测 `"- A  ␊␊"` → 列表被截断并多出一个游离段落） | `<br>`（保结构） |
| **顶层段落**的段末换行 | 行尾两空格会被解析器吞掉 | `"  ␊"`（见 §2.4 —— 按用户反馈**不再**用 `<br>`） |

同时**恢复「续行行首转义」**（v0.12.2 曾随回车语义一并回退，导致该数据损坏面重新暴露）：

- 回车换行后写 `---` / `===` → 此前会把**上一段吞成 Setext 标题**且字面文本永久丢失；现自动写成 `\---` / `\===`
- 回车换行后写 `- ` / `+ ` / `* ` / `1. ` / `# ` / `> ` / ```` ``` ```` / `~~~` / `[^1]:` / 链接引用定义 / HTML 块 → 此前会把段落拆成列表 / 标题 / 引用；现按 21 类危险构造转义续行行首
- 表格单元格路径不做续行转义（表格内换行统一写 `<br>`，不出现真实换行）

> 本意就是列表 / 标题 / 引用时，请先 `Shift+回车` **新建段落**再输入 —— 新段落的行首是块级语法该在的位置，不会被转义。

### 2.4 【二轮反馈】段末换行不再写 `<br>`

**现象**：刚按完回车、还没输入下一行就切到编辑/分屏模式，源码里出现 `第一行<br>` —— 看起来像"回车没了、多了一串标签"。

**修复**：**顶层段落**的段末硬换行改为写成两空格换行，源码里就是"多了一个换行"：

| | 修复前 | 修复后 |
|---|---|---|
| 顶层段落源码 | `第一行<br>␊` | `第一行␠␠␊` |

同时顶层段落**不再追加段落终止换行** —— 否则 `"A  ␊"` + `"␊"` = `"A  ␊␊"` 会被解析成一个空段落（实测往返后 doc 多出一个块）。

**为什么只在顶层段落改**：段末换行在 Markdown 里本就**无法表达**（行尾两空格会被解析器吞掉），而列表项 / 引用的序列化会把内容嵌进 `- ` / `> ` 前缀行，内嵌换行会拆块（实测列表被截断 + 多出游离段落）。这两处仍用 `<br>` 保结构，且它们通常不会产生段末换行（列表内回车 = 分裂条目）。

**代价（与 CommonMark 及其他编辑器一致）**：刚按完回车就保存/关闭时，段末那个空行**不随文件重开保留**；想让它存盘保留请连按两次回车或 `Shift+回车`（得到真正的段落）。切换模式不会丢（切换走的是同一份 doc，只有重新读文件才会重新解析）。

### 2.5 【二轮反馈】行高设置三模式生效（编辑区 + 分屏两侧）

**现象**：把设置 → 排版 →「行高」调到 1.8 以外，只有阅读区变了，**编辑区与分屏右侧不变**。

**根因（两处，都实测确认）**：

1. 编辑区 `textarea.source-editor` 的 `line-height` **硬编码 1.8**（阅读区用的是 `var(--editor-line-height, 1.8)`）；
2. 分屏右侧是 **iframe 独立文档，不继承父文档的 CSS 变量** —— 虽然 v0.12.2 P8 把右侧样式从硬编码改成了 `var(--editor-line-height, 1.8)` 等，但变量从未注入 iframe 自己的 `:root`，于是**恒取兜底值**，右侧实际仍不跟随（段间距、内容区宽度两项同病）。

**修复**：

- `.source-editor { line-height: var(--editor-line-height, 1.8) }` —— 打字机滚动、视口锚点、专注遮罩都在运行时读 `getComputedStyle(textarea)` 的 line-height，故自动跟随；
- 把 **行高 / 段间距 / 内容区宽度**三项注入 iframe 的 `:root`；正文与排版**同时**变化时也刷新 iframe 样式表（否则右侧会停在旧行高）。

**headless Chrome 实测**（设置「行高 = 2.2」）：

| 区域 | 修复前 | 修复后 |
|---|---|---|
| 阅读区 `.ProseMirror` | 35.2px | 35.2px |
| 编辑区 `textarea` | **28.8px** ❌ | **35.2px** ✅ |
| 分屏右侧 iframe 内部 body | **28.8px** ❌ | **35.2px** ✅ |
| 分屏右侧段落 margin | 12.8px（兜底 0.8em） | 12.8px（按设置注入并消费） |

### 2.6 保留的 v0.12.2 成果

本版不影响 v0.12.2 的九项缺陷收敛：Emoji 白屏（P0）、图片 `|300` 宽度丢失、跨块选区回车守卫、`$`/`==` 转义噪音、改标题后锚点/目录失配、分屏双重缩放、三模式焦点保持与进度、导出样式跟随设置、i18n 收口。

其中**跨块选区回车**的守卫在本版继续保持：非空选区一律交回 `splitBlock`，不会走 `replaceSelectionWith(hard_break)` 而把两段合并。

## 四、已知范围

- **段末换行不随文件重开保留**：Markdown 无法表达"段末换行"（行尾两空格会被解析器吞掉），故刚按完回车就保存/关闭时，那个空行会消失（CommonMark 与其他编辑器同样如此）。列表项 / 引用内的段末换行改用 `<br>` 保结构，因此**会**保留；顶层段落若想保留空行，请连按两次回车或 `Shift+回车`（得到真正的段落）。**切换模式不会丢**（走的是同一份 doc，只有重新读文件才会重新解析）。
- **DOCX / EPUB / LaTeX 仍无样式定制入口**（PDF 有），属未实现功能，非缺陷。
- 未支持：跨文件全文搜索、标签、frontmatter、双链/反链/图谱、书签、Git 集成、合并单元格等（详见 README）。

## 五、升级说明

- **直接覆盖安装即可**，无破坏性变更；设置、快捷键、收藏、最近打开、会话（含未保存标签）等本地数据全部保留。
- **回车手感变化**：普通段落内回车不再"另起一段"，而是**换行**（源码里两行相邻）。这是为了与阅读模式所见一致（也是 v0.12.1 需求10 的本意，v0.12.2 因观感问题回退，本版把观感与往返保真一起修好）。
  - 想要**新段落**（源码空行）→ `Shift+回车`，或**连按两次回车**
  - 列表 / 任务项 / 引用 / 标题 / 表格内回车**行为不变**
- **旧文档**：此前用回车产生的空行会原样保留，不会被改写；只有新输入的回车才按新语义保存。
- **在换行后写块级语法**：本版已自动转义行首（`\- `/`\# `/`\---` 等），不会再被吞成列表 / 标题；若本意就是列表或标题，请先 `Shift+回车` 新建段落再输入。
- **段末换行（二轮）**：刚按完回车就切模式，源码里是"多了一个换行"，**不再出现 `<br>`**。但 Markdown 无法表达段末换行 —— 若此刻直接保存/关闭，重开后那个空行不保留（CommonMark 与其他编辑器同样如此）；想让它存盘保留请连按两次回车或 `Shift+回车`。切换模式不会丢。
- **行高（二轮）**：设置里的「行高 / 段间距 / 内容区宽度」现在**三模式全部生效**（此前编辑区固定 1.8、分屏右侧固定兜底值）。原有文档观感不变（默认值未改）。
